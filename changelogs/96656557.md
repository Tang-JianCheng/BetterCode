## 修改摘要

为 BetterCode 增加统一的子 Agent 委派系统：稳定的 `agent` 工具支持定义式角色和 Fork 两条路径，角色可从插件、内置、用户和项目四级来源加载并热更新。每个子 Agent 隔离消息、上下文、权限、读取缓存、Token 与取消状态，复用现有 Agent Loop、Provider、Hook、MCP 和项目文件系统；定义式任务支持前台执行、显式后台、120 秒自动后台和 `Ctrl+B` 手动后台，Fork 强制后台并继承父请求合法前缀与工具顺序。

后台任务由统一状态机追踪，`/tasks` 可查询列表和详情，完成结果不会主动唤醒模型，而是在下一次自然请求中以内部指令回流并持久化。Hook 的 agent 动作现已连接真实定义式子 Agent，scoped runtime 隔离 Prompt 队列并阻止递归委派；shared Skill 保留 agent，isolated Skill 和所有子 Agent 永久移除 agent/load_skill。会话清空、恢复和关闭会取消旧任务并隔离迟到结果。

## 安全边界

- 子 Agent 非交互运行，default/strict 未明确允许的工具会作为权限拒绝回灌模型。
- 危险命令黑名单、项目路径沙箱、权限规则、Plan Mode 和 Hook 拒绝继续生效。
- 后台工具按角色白名单再次收窄，模型伪造不可见工具不会执行。
- 后台任务不跨进程恢复，不创建 Worktree，并发文件写入不自动合并。
