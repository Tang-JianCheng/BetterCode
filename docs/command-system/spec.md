# BetterCode 命令系统 Spec

## 背景

BetterCode 当前在终端组件中用一组条件分支识别斜杠命令。命令元数据、解析、执行和界面状态混在同一个提交入口里，新增命令容易产生撞名、帮助文本遗漏和行为不一致；输入补全也无法复用这些定义。

本章建立统一的命令注册与分发机制。斜杠输入不进入 Agent Loop，直接执行确定性的本地动作、界面动作或预设提示词；普通输入仍按当前 Agent 模式发送给模型。

## 目标

- G1：命令定义、解析、分发和补全共享同一份注册元数据。
- G2：本地命令绕过模型，减少延迟和 Token 消耗。
- G3：命令实现只依赖抽象界面控制能力，不依赖 Ink。
- G4：计划模式成为会话级状态，状态栏始终显示 `[DEFAULT]` 或 `[PLAN]`。
- G5：保留现有恢复、权限、回滚和退出能力的兼容入口。

## 功能需求

- F1：注册中心管理名称、别名、描述、用法、命令类型、可选参数提示、隐藏标记和处理函数。名称与别名统一按小写登记。
- F2：启动阶段检测名称、别名之间的全部冲突；任意撞名立即抛出启动错误，程序不得进入交互界面。
- F3：解析器只处理以 `/` 开头的输入；第一个空白前为命令名，之后去除首尾空白作为参数。命令名大小写不敏感，空输入和非命令输入早返回。
- F4：未知命令返回包含原命令和 `/help` 引导的确定性错误，不发送给模型。
- F5：命令分为 `local`、`ui`、`prompt` 三类。前两类只执行本地或界面动作；`prompt` 类把预设提示词作为用户任务发送给 Agent。
- F6：界面控制接口至少支持显示消息、发送用户任务、切换与读取 Agent 模式、读取 Token 使用量、刷新状态；会话、记忆、权限、压缩、清理等现有动作也通过该接口暴露。
- F7：用户回车入口先交给命令分发器；命令已处理时停止，普通输入才按当前模式送入 Agent Loop。
- F8：注册中心提供基于命令名和别名的补全候选。隐藏命令不参与补全；单候选直接补为规范主命令，多候选展示可选择菜单。
- F9：内置十个主命令：`/help`、`/compact`、`/clear`、`/plan`、`/do`、`/session`、`/memory`、`/permission`、`/status`、`/review`。
- F10：`/plan` 将当前模式切换为计划模式，后续普通输入使用只读工具；`/do` 切回默认执行模式。切换不自动发送模型请求。
- F11：`/review [范围]` 是提示词命令，生成固定代码审查任务并交给 Agent；审查结果优先报告 bug、回归、安全风险和缺失测试。
- F12：`/session` 显示当前会话和近期会话，`/session <id>` 恢复指定会话；旧 `/resume` 与 `/r` 作为别名继续可用。
- F13：`/permission [strict|default|allow]` 无参数显示状态，有参数切换权限模式；旧 `/permissions` 作为别名继续可用。
- F14：`/status` 展示 Provider、Agent 模式、权限模式、当前会话、Token 用量和记忆数量，并触发状态刷新。
- F15：现有 `/rewind`、`/exit`、`/quit` 作为隐藏兼容命令继续工作，但不出现在主帮助和补全列表中。

## 非功能需求

- N1：解析与补全不执行文件或网络 I/O，候选查询为内存操作。
- N2：注册顺序稳定，帮助和补全结果按注册顺序输出。
- N3：命令处理异常被转换为可读消息，不使 TUI 崩溃。
- N4：注册、解析、分发、补全和内置命令可用假界面控制器独立测试。
- N5：新增源码注释和 Git 提交信息使用中文，系统名称统一为 BetterCode。

## 不做的事

- 不支持用户自定义命令或配置文件扩展。
- 不动态生成提示词模板。
- 不增加命令级权限系统。
- 不把命令注册机制扩展成 Skill 或插件加载器。
- 不改变 Agent 工具权限、上下文压缩和长期记忆的底层实现。

## 验收标准

- AC1：构造两个共享名称或别名的命令时，注册阶段同步抛出冲突错误。
- AC2：`/HeLp` 能命中 help；`/review src/chat` 解析出规范名称和参数 `src/chat`。
- AC3：普通文本不被命令系统处理；未知 `/missing` 显示 `/help` 引导且 Provider 调用数不增加。
- AC4：十个主命令都能从注册中心列出，帮助内容来自注册元数据。
- AC5：`/plan` 后状态栏显示 `[PLAN]`，下一条普通任务使用 Plan Mode；`/do` 后显示 `[DEFAULT]`，下一条任务恢复完整工具。
- AC6：`/review parser` 只触发一次 Agent 请求，发送内容包含审查准则和 `parser` 范围。
- AC7：`/session`、`/memory`、`/permission`、`/status`、`/clear`、`/compact` 均绕过普通对话分支。
- AC8：输入唯一前缀并按 Tab 直接补全；输入共享前缀显示菜单；隐藏命令不出现在候选中。
- AC9：旧 `/resume`、`/permissions`、`/rewind`、`/exit`、`/quit` 仍可执行。
- AC10：类型检查、全量测试和差异检查全部通过。

## 增量：/session 交互选择器与会话摘要

### 变更背景

原 `/session` 无参数时直接输出会话 ID 表格，用户需要手动复制 ID 再输入恢复，会话描述使用首条任务，长会话列表不可浏览也不可删除。本增量把 `/session` 改为终端内交互选择器，并让每个会话展示一句简短摘要。

### 变更内容

- `/session` 无参数时打开交互会话选择器：方向键上下选择，Enter 恢复选中会话，Esc 退出；Delete 或 Backspace 删除选中会话，当前会话不可删除。
- 选择器沿用命令面板的左右分栏风格：左侧展示会话摘要，右侧展示消息数量与修改时间；选中行整行反色高亮，超过一页时可滚动并显示剩余候选数。
- 会话描述改为摘要而非首条任务：每次 Agent 自然完成后在后台用 LLM 生成一句不超过 100 字的中文摘要，写入 JSONL 的 `session_summary` 系统记录；旧记录被新记录替换，不随对话增长。
- 没有摘要的旧会话在列表展示时回退为最近一条用户消息，保证描述始终反映会话最近状态而非第一条任务。
- 会话摘要与删除能力不改变 `/session <id>` 直接恢复语义；旧 `/resume` 与 `/r` 别名继续可用。

### 验收补充

- AC11：`/session` 无参数时显示可交互选择器，方向键能循环或翻页选择，Enter 恢复选中会话，Esc 退出且不产生 Agent 请求。
- AC12：选择器支持 Delete/Backspace 删除非当前会话，删除后列表即时刷新；对当前会话删除被拒绝并给出明确提示。
- AC13：会话列表展示的是摘要（`session_summary` 或最近用户消息回退），不再使用首条任务；摘要生成失败不影响列表与恢复。
- AC14：摘要以 `session_summary` 系统记录持久化，更新时替换旧摘要；`/session <id>` 直接恢复与压缩边界重建不受摘要记录影响。
