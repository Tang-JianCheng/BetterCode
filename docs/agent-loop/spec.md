# MewCode Agent Loop Spec

## 背景

当前 MewCode 已具备六个核心工具、统一工具注册中心、双协议流式工具调用解析和单次工具结果回灌能力。模型可以读取、写入、修改和搜索项目，也可以执行命令，但每次用户提问最多只执行一个工具，拿到结果后不会继续自主行动。用户必须反复发送消息才能推动一个多步骤任务完成。

本章在现有工具系统之上增加 Agent Loop。MewCode 将按照“请求模型、执行工具、回灌结果、继续判断”的方式自主迭代，直到模型给出不再需要工具的最终回复，或命中明确的停止条件。同时提供只允许分析项目并输出计划的 Plan Mode，以及从最近计划直接进入执行的 `/do` 流程。

## 目标

- 让 MewCode 能在一次用户请求内自主完成多轮模型推理和工具执行。
- 用统一的异步事件流向界面报告文本、Thinking、工具调用、工具结果、Token 用量、进度和停止状态，使 Agent 编排不依赖终端界面。
- 在保持文本实时展示的同时，可靠收集每轮完整模型响应，用于历史记录和下一轮判断。
- 支持模型在同一轮请求多个工具，并根据工具是否有副作用选择并发或串行执行。
- 提供 `/plan <任务>` 和 `/do` 两段式工作流，保证计划阶段只能观察项目，执行阶段可以使用全部工具。
- 为自主循环提供可预期的停止边界，避免无限运行或在异常状态下反复重试。

## 功能需求

- **F1：自主 Agent Loop**  
  用户提交普通任务后，MewCode 必须启动自主循环。每轮先请求模型；若模型请求工具，则执行工具并把调用及结果加入同一对话历史，再自动进入下一轮；若模型未请求工具，则把该轮文本作为最终回复并正常结束，无需用户继续催促。

- **F2：完整对话回灌**  
  每轮模型产生的完整文本、工具调用及每个工具对应的结构化结果都必须按调用标识加入历史。后续轮次必须能够看到此前所有成功或失败的工具结果，并据此调整行动。

- **F3：双路流式收集**  
  模型流式返回期间，文本和 Thinking 增量必须立即作为事件向消费方发送；同时，系统必须在后台收集该轮完整文本、Thinking、工具调用和用量信息。流结束后，收集结果用于循环判断和历史写入，实时展示与完整收集不能互相阻塞或产生内容差异。

- **F4：统一异步事件流**  
  Agent 必须通过单一异步事件流报告运行过程，至少覆盖正文文本增量、Thinking 增量、工具调用、工具结果、Token 用量、循环进度、错误和最终停止状态。事件必须携带足够的调用标识、轮次或停止原因，使界面无需读取 Agent 内部状态即可正确展示一次运行。

- **F5：循环进度**  
  每轮开始、模型响应完成、工具执行开始和工具执行完成时，必须产生可观测进度。进度至少说明当前轮次、最大轮次和当前阶段，便于界面显示 Agent 正在思考、执行工具或收尾。

- **F6：Token 用量**  
  Provider 返回 Token 用量时，Agent 必须将本轮用量和当前运行的累计用量通过事件报告。Provider 未返回用量时不得伪造数字，也不得因此导致循环失败。

- **F7：多工具调用执行**  
  模型在同一轮返回多个工具调用时，MewCode 必须处理全部调用，并为每个调用生成独立结果。结果按模型原始调用顺序回灌，保证调用标识和结果一一对应。

- **F8：按副作用调度工具**  
  六个核心工具必须分为只读工具和有副作用工具。读取文件、查找文件、搜索代码属于只读工具，可在同一批次内并发执行；写入文件、修改文件、执行命令属于有副作用工具，必须按模型给出的顺序逐个执行。一次响应同时包含两类工具时，先并发完成只读工具，再按原始顺序串行执行有副作用工具。

- **F9：工具失败可恢复**  
  工具参数错误、路径错误、执行失败和超时仍按现有结构化结果回灌，不得直接终止 Agent Loop。模型可以在下一轮根据错误修改参数或选择其他工具，除非同时命中其他停止条件。

- **F10：正常完成停止**  
  当模型完成一轮响应且没有请求工具时，Agent 必须正常停止，保存完整最终文本，并发出明确的完成事件。纯聊天请求也通过同一规则在首轮结束。

- **F11：迭代上限停止**  
  单次 Agent 运行最多执行 10 轮。每轮定义为一次模型请求以及该响应请求的工具执行；第 10 轮完成后不得发起第 11 次模型请求。若第 10 轮仍请求工具，完成该轮工具结果回灌后以“达到迭代上限”停止，并保留已产生的历史和结果。

- **F12：用户取消停止**  
  Agent 运行期间，用户可以取消当前运行。取消信号必须传递给正在进行的模型请求或工具执行，阻止后续轮次启动，并以“用户取消”状态结束；已完成的消息和工具结果保留。取消当前任务不得等同于退出 MewCode，取消后用户仍可继续对话。

- **F13：连续未知工具停止**  
  模型请求未知或当前模式不可用的工具时，系统必须返回结构化的“工具不可用”结果供模型调整。连续出现 3 个未知或不可用工具调用后，Agent 以“连续未知工具”停止；任意已注册且当前模式允许的工具调用会重置连续计数。多个调用按模型原始顺序计数。

- **F14：流错误停止**  
  模型流在建立、读取、解析或结束前发生错误时，Agent 必须停止当前运行，发出错误及“流错误”停止事件，不再执行该轮尚未确认完整的工具调用，也不启动下一轮。此前已完成轮次的历史保持可用。

- **F15：Plan Mode 入口**  
  用户输入 `/plan <任务>` 时，MewCode 必须立即针对该任务启动只读 Agent Loop。计划阶段只向模型开放读取文件、查找文件和搜索代码三个只读工具，并在同一对话中保存模型最终输出的计划。

- **F16：Plan Mode 只读边界**  
  计划阶段即使模型构造或猜测写文件、改文件、执行命令等调用，也不得执行任何副作用操作，必须将其作为当前模式不可用的工具结果处理。计划阶段沿用正常循环的停止条件、事件流和 10 轮上限。

- **F17：执行最近计划**  
  用户输入 `/do` 时，MewCode 必须在当前会话中找到最近一次成功完成的计划，恢复全部六个工具，并自动基于该计划启动执行，无需用户重复输入任务内容。执行过程使用正常 Agent Loop，最终回复和执行记录继续保存在同一对话中。

- **F18：计划状态管理**  
  当前会话可以产生多个计划，`/do` 只执行最近一次成功完成的计划。计划被取消、发生流错误或达到其他异常停止条件时，不得替换此前成功计划；清空会话后不再保留可执行计划。没有可用计划时输入 `/do`，系统必须给出明确提示且不调用模型或工具。

- **F19：界面状态与命令**  
  终端界面必须能够消费 Agent 事件，持续展示流式文本、Thinking 和当前进度，并在工具执行及多轮切换期间保持一次连续运行。帮助信息必须包含 `/plan`、`/do` 和运行中取消方式；运行结束或取消后恢复输入。

## 非功能需求

- **N1：协议兼容性**  
  Agent Loop、完整工具回灌和 Token 用量采集必须兼容现有 Anthropic 与 OpenAI 兼容 Provider，包括 DeepSeek。Agent 层不得依赖某个供应商的原始事件格式。

- **N2：界面解耦**  
  Agent 核心不得导入或调用 Ink/React。命令行界面只负责启动、取消和消费异步事件；测试或其他界面可以使用同一 Agent 接口。

- **N3：事件顺序确定性**  
  单次运行的进度、工具调用、工具结果和停止事件必须有确定顺序。并发只读工具可以以任意实际完成顺序结束，但对外结果回灌及对应的结果事件必须按模型原始调用顺序输出。

- **N4：取消响应性**  
  收到取消后不得启动新的模型请求或工具调用。支持中止信号的在途操作应尽快结束；不支持立即中止的底层操作即使稍后返回，其结果也不得推动新一轮循环。

- **N5：稳定性**  
  工具失败、未知工具、取消、达到迭代上限或模型流错误都不得导致主进程崩溃。一次 Agent 运行结束后，MewCode 必须能继续接受新任务。

- **N6：向后兼容性**  
  普通无工具聊天、Thinking 展示、双协议 Provider、六个工具的路径边界与超时、`/help`、`/clear`、`/exit` 和 `/quit` 的既有行为必须保持可用。原先的单工具限制提示由 Agent Loop 行为取代。

- **N7：资源边界**  
  每次运行的模型请求次数受 10 轮上限约束；每个工具仍使用既有超时和输出大小限制。并发只限同一模型响应内的只读工具，不跨轮并发模型请求。

- **N8：可测试性**  
  循环、停止原因、事件顺序、并发与串行调度、计划模式和执行模式必须可用 Fake Provider 与 Fake Tool 独立自动化验证，不依赖真实 LLM API 或交互式终端。

- **N9：平台范围**  
  保持当前 macOS 和 Linux 目标平台，不新增 Windows 兼容要求。

## 不做的事

- 不实现工具权限系统、危险命令审批、用户交互式确认或按项目配置权限。
- 不实现对话上下文压缩、摘要、裁剪、持久化或跨进程恢复。
- 不实现 Agent 运行中的追问、补充信息请求或其他人机交互式暂停点。
- 不新增工具；继续使用现有六个核心工具。
- 不实现任务图、长期记忆、子 Agent、后台任务或跨会话并行 Agent。
- 不允许多个模型请求并发；每轮模型响应完整收集后才进入工具调度或下一轮。
- 不承诺强制终止无法响应取消信号的任意第三方或系统操作，只保证其迟到结果不会继续驱动循环。
- 不改变现有项目根目录边界、命令工作目录约束、工具参数 Schema、输出截断和错误结构。
- 不新增 Plan 文件持久化；计划只存在于当前进程的当前会话中。
- 不实现 `/do` 选择历史计划、编辑计划或为 `/do` 追加临时执行要求。
- 不增加复杂工具时间线、权限弹窗或多面板 TUI；本章只提供必要的运行进度与取消反馈。

## 验收标准

- **AC1：多轮自主完成**  
  使用一个依次请求“读取文件、修改文件、再次读取、最终回答”的 Fake Provider 运行普通任务时，用户只提交一次输入；系统自动完成所有轮次，最终文本与实际文件内容一致。（覆盖 F1、F2）

- **AC2：无工具首轮结束**  
  模型首轮只返回文本时，不执行任何工具、不发起第二次模型请求，并以正常完成状态结束。（覆盖 F1、F10）

- **AC3：双路收集一致**  
  将正文、Thinking 和两个工具调用拆成多个流片段后，消费方在流期间逐片收到增量，流结束得到的完整响应与所有片段拼接结果及工具调用完全一致。（覆盖 F3）

- **AC4：事件流完整性**  
  一次包含两轮和工具执行的运行会依次产生进度、文本或 Thinking、工具调用、工具结果、用量及唯一停止事件；每个事件均能关联到正确轮次或调用标识，Agent 核心无需 Ink 即可运行。（覆盖 F4、F5、N2、N3）

- **AC5：Token 用量累计**  
  Fake Provider 在两轮分别报告输入和输出 Token 后，事件同时给出正确的每轮值与累计值；不报告用量的 Provider 可以正常完成且不产生虚假用量。（覆盖 F6）

- **AC6：只读工具并发**  
  同一响应请求三个带可控延迟的只读工具时，三者均在前一个完成前启动，总耗时符合并发执行特征；工具结果事件和历史仍按原始调用顺序排列。（覆盖 F7、F8）

- **AC7：副作用工具串行**  
  同一响应按顺序请求写入、修改和命令工具时，后一工具只在前一工具结束后启动，实际副作用顺序与模型调用顺序一致。（覆盖 F7、F8）

- **AC8：混合工具调度**  
  同一响应混合只读和有副作用工具时，只读工具先并发完成，有副作用工具随后按原始相对顺序逐个执行；每个调用都只执行一次并得到对应结果。（覆盖 F7、F8）

- **AC9：失败后调整**  
  工具首次返回参数错误或执行错误后，该错误被回灌；模型下一轮可以提交修正后的调用并继续到正常完成，主进程不中断。（覆盖 F2、F9、N5）

- **AC10：迭代上限**  
  模型每轮都请求工具时，系统恰好最多发起 10 次模型请求；第 10 轮的工具完成回灌后不再请求模型，并以达到迭代上限停止。（覆盖 F11、N7）

- **AC11：用户取消**  
  在模型流式返回期间和工具执行期间分别触发取消，当前操作收到取消信号，不启动下一轮，最终停止原因均为用户取消；随后可以提交新任务并正常运行。（覆盖 F12、N4、N5）

- **AC12：连续未知工具**  
  模型连续请求三个未知或模式不可用工具时，每次都得到结构化不可用结果，第三次后停止且不发起下一轮；中间出现一次允许的已注册工具时，计数重置。（覆盖 F13）

- **AC13：流错误隔离**  
  分别模拟连接失败、流片段解析失败和流提前中断时，Agent 发出错误与流错误停止事件，不执行未完整聚合的工具调用，不启动下一轮，并可继续处理之后的新任务。（覆盖 F14、N5）

- **AC14：只读计划生成**  
  输入 `/plan <任务>` 后，模型请求读取、查找和搜索工具均可执行，最终计划保存于当前会话；本次请求从未向模型开放写入、修改或命令工具。（覆盖 F15）

- **AC15：计划模式拒绝副作用**  
  Plan Mode 中模型猜测调用写入、修改或命令工具时，项目内容保持不变，调用收到当前模式不可用结果，并按未知工具规则继续或停止。（覆盖 F13、F16）

- **AC16：执行最近计划**  
  连续成功生成两个计划后输入 `/do`，系统不要求重复任务文本，向模型提供第二个计划的既有对话上下文并开放全部六个工具，执行记录和最终回复继续追加到当前会话。（覆盖 F17、F18）

- **AC17：无可用计划**  
  新会话、执行 `/clear` 后，或只有失败/取消计划时输入 `/do`，界面明确提示没有可执行计划，Provider 与工具均未被调用。（覆盖 F18）

- **AC18：终端交互回归**  
  普通聊天仍实时显示正文和 Thinking；Agent 运行时显示当前轮次及阶段，取消后恢复输入；`/help` 展示 `/plan`、`/do` 和取消方式，既有 `/clear`、`/exit`、`/quit` 仍可用。（覆盖 F19、N6）

- **AC19：双协议回灌**  
  Anthropic 与 OpenAI 兼容 Provider 各自完成至少两轮、同轮多个工具调用和多个工具结果回灌；下一轮能正确关联全部调用与结果，Provider 报告的用量能进入统一事件流。（覆盖 F2、F6、N1）

- **AC20：独立自动化验证**  
  不访问真实 LLM API、不启动交互式终端即可自动验证正常完成、10 轮上限、取消、连续未知工具、流错误、并发只读、串行副作用、Plan Mode 和 `/do`。（覆盖 N8）

- **AC21：项目回归检查**  
  项目类型检查与全部自动化测试在目标 macOS 环境通过；现有六个工具的路径边界、超时、输出截断和双协议流式解析测试继续通过，实现不引入仅 Windows 可用的行为。（覆盖 N6、N9）
