# 项目记忆与会话持久化 Spec## 背景

BetterCode 默认是无状态的：每次启动都是全新会话，不知道用户是谁、项目有什么规范、上次聊到哪儿。前面章节解决了"单进程长时间运行不崩"的问题，但进程一退出，对话历史和工作上下文就全丢了。

实际编码场景里，用户会反复回到同一个项目，有稳定的编码规范、个人偏好、未完成的工作。每次重新解释一遍这些上下文，既浪费时间又容易遗漏。

本章要补的就是"跨会话的记忆"，让 Agent 从"每次失忆"变成"越用越懂你"。靠三条独立线索——项目指令文件、会话存档、后台自动笔记——实现工作记忆（会话级）和长期记忆（项目/用户级）的分层管理，进程中断之后也能平滑接着用。

设计上分三个独立层次。第一层是项目指令文件：用户手写的 Markdown，支持沿目录路径分层发现、对其他文件的内联引用、循环检测；加载结果作为对话首条系统提醒注入，让 Agent 从第一轮就遵循项目约定。第二层是会话存档：对话历史以追加方式实时写入磁盘，压缩时写入一个边界记录把摘要和保留尾部一同内联；崩溃最多丢最后一行，用户可通过命令从历史会话中恢复。第三层是后台自动笔记：每轮 Agent 自然停下后异步调模型提取值得记住的信息，分类后按来源路由到项目级或用户级目录，并自动重建索引；下次启动时索引连同项目指令一起注入到对话首条系统提醒上。

三层互相独立但配合作战：指令文件提供静态规范，会话存档提供工作记忆和崩溃恢复，自动笔记提供演化的长期记忆。

## 目标

- G1：新会话启动时自动加载项目指令和记忆摘要，Agent 通过对话首条系统提醒就能感知项目规范、用户偏好。
- G2：对话历史以追加方式写入磁盘，崩溃最多丢最后一行；恢复时能识别压缩边界、跳过坏行和空内容。
- G3：用户可通过"列出会话"和"按 ID 恢复指定会话"两种交互从历史会话中恢复。
- G4：Agent 自然停下后由钩子触发后台异步笔记提取，无需用户手动管理；并发的二次请求自动合并为尾部运行，避免抖动。
- G5：项目指令支持对项目内相对路径、用户主目录路径、绝对路径三种内联引用形式，以行首特殊符号触发；带循环检测、深度上限，并跳过代码块内出现的同名行。
- G6：所有新增机制对现有 Agent 主循环影响最小——指令和记忆在初始化阶段一次性注入并保证幂等；笔记提取通过异步钩子执行，不阻塞下一轮。
- G7：长期未修改的会话存档在调用清理动作时被删除，防止磁盘无限增长。
- G8：会话 ID 由统一函数生成，毫秒时间戳为前缀以保证天然可排序，附带随机后缀防同秒碰撞；恢复会话后切换为被恢复的会话 ID，新消息追加到同一份存档。

## 功能需求### 第 1 层：项目指令文件- **F1**：启动时按以下顺序扫描并拼接指令源（越靠后优先级越高，模型注意力优先关注后面的内容）：① 用户全局目录下的项目指令文件与代理指令文件；② 从仓库根目录到工作目录路径上每一层目录的项目指令文件与代理指令文件；③ 工作目录下子目录中的旧版指令文件（兼容历史格式）；④ 工作目录下的本地私有覆盖文件。
- **F2**：每条加载结果包装成带文件来源前缀的段落，多段之间用分隔线隔开，便于模型识别来源。
- **F3**：内联引用语法：行首以特定触发符开头，紧跟项目内相对路径、用户主目录路径或绝对路径，不含空白。触发符出现两次时视为转义、不识别；含空白的同类行（如用户名标注）跳过；代码块内的同类行不识别。
- **F4**：内联引用嵌套深度由上限常量限制；超过深度的层级保留原文不展开，递归静默返回，不报错。
- **F5**：内联引用循环检测：维护一个已展开绝对路径集合，同一个绝对路径只展开一次；命中已展开路径保留原引用行不替换。
- **F6**：找不到的文件、读取失败、路径无法解析都静默跳过，不抛错；成功展开的位置在被引用内容前插入一行 HTML 风格注释标注来源，便于定位。
- **F7**：长期记忆索引由记忆管理器扫描两级记忆目录后生成：每条笔记摘要为一行"标识、类型、描述"的列表项，统一加上提示前缀返回；目录为空时返回空字符串。
- **F8**：会话管理器在初始化阶段调用一次注入动作，把指令文本和记忆文本拼接成一段系统提醒写到对话首条；通过幂等标志确保进程生命周期内最多注入一次。

### 第 2 层：会话存档#### 会话 ID 与文件- **F9**：会话 ID 由统一函数生成，形如"按 36 进制编码的毫秒时间戳"加上"短随机十六进制后缀"，前者保证天然可排序，后者防同秒碰撞。
- **F10**：会话存档目录固定在工作目录下；单个会话存档路径由"目录加会话 ID 加扩展名"的方式派生。任务清单、文件历史等周边数据通过各自的存储派生路径，不与存档同目录。

#### 存档行格式- **F11**：每条消息序列化为一行 JSON，字段至少包括：
  - 角色（必需）：用户 / 助手 / 系统
  - 内容（必需）：消息正文
  - 时间戳（必需）：调用方写入的 ISO 时间
  - 类型（可选）：普通消息为空；压缩边界用专用类型标识
  - 工具调用标识（可选）：保留字段，用于工具调用链恢复
- **F12**：压缩边界行：当触发压缩时，写入一条"系统角色 + 压缩边界类型"的特殊行，其内容是包含摘要正文和需要保留的尾部消息的结构化数据。保留的尾部仅含角色与正文，恢复时可直接重放而无需再回溯边界以前的位置。
- **F13**：追加时机：用户输入入队时写入一次用户消息；Agent 完成本轮并产出最终回复时写入一次助手消息；用户主动压缩与 Agent 内部自动压缩分别在各自时机写入压缩边界。
- **F14**：崩溃安全：所有写入使用追加模式，进程崩溃最多丢失最后一行不完整写入。读取时对每一行单独解析，解析失败的行跳过；内容为空的普通消息也跳过。

#### 会话列表与恢复- **F15**：列出会话时扫描存档目录下所有会话存档：每个文件遍历所有行，统计有效消息数；提取第一条用户消息且正文非空的前若干字符作为标题；读取文件大小与最后修改时间；最终按最后修改时间倒序排列。
- **F16**：读取单个会话时按行解析，保留正文非空的行（包括压缩边界行，因为其正文是结构化数据）。
- **F17**：把磁盘记录重建为可重放的消息序列时遵循以下规则：
  - 从尾部反向找最后一个压缩边界记录；
  - 命中：先把边界正文反序列化，把摘要包装成一段中文用户消息（前置"本次会话延续自之前的对话，因上下文空间不足进行了压缩。以下是早期对话的摘要：…"，尾部若有保留尾部则追加"近期消息已原样保留。"），随后逐条追加保留尾部中的用户/助手消息，最后把边界之后的普通消息按角色过滤追加；
  - 未命中（旧会话或从未压缩过）：全量重放每一条用户/助手消息；
  - 边界以前的原始消息保留在文件里但不参与重放——这是压缩跨恢复仍然生效的关键。
- **F18**：会话恢复通过 TUI 内置命令触发：
  - 不带参数：列出最近若干个会话作为系统消息回显，每条形如"会话 ID（消息数）— 首条用户消息标题"，提示用带参形式恢复；
  - 带参数：读取目标会话，空结果回显未找到；否则新建会话管理器、重新注入指令与记忆、按重建出的消息序列依次回放、切换当前会话 ID、关联的任务清单等周边存储重新指向新 ID；TUI 在恢复内容之后追加一条系统消息标注已恢复，并同步内部索引避免重渲染抖动。
- **F19**：恢复后所有新消息追加到同一份存档；后续写入继续走相同路径，行号继续递增。

#### 会话清理- **F20**：清理动作遍历会话存档目录，对每个文件读取最后修改时间；超过过期天数（常量）的存档被删除，返回删除数量。
- **F21**：清理是尽力而为的：列目录失败返回 0；单个文件读取或删除失败静默跳过，不影响其他文件；不抛异常。

### 第 3 层：自动笔记#### 笔记存储- **F22**：笔记分四类：用户偏好、纠正反馈、项目知识、参考资料。
- **F23**：每条笔记是独立 Markdown 文件，顶层带 YAML frontmatter，其中包含标识、描述、类型三段，正文紧随其后。
- **F24**：双路路由：项目知识与参考资料写入项目级记忆目录；用户偏好与纠正反馈写入用户全局记忆目录。两个目录由记忆管理器统一扫描和管理。
- **F25**：每次写入新笔记后，记忆管理器立即重建项目级目录下的索引文件：扫描两级目录的全部笔记（排除索引自身）、读 frontmatter 中的标识与描述、按标识字母序生成"标识、相对路径、描述"格式的列表行；总长度设有行数和字节双重上限，超出后以最后一个换行为边界截断。
- **F26**：文件名由提取模型自由产出，无强制类型前缀。frontmatter 解析兼容旧版顶层类型字段与新版嵌套于元数据下的写法。

#### 记忆注入- **F27**：启动时先加载项目指令得到指令文本，再让记忆管理器扫描得到记忆摘要文本，最后调用会话管理器的注入动作把两段拼成一条系统提醒写到对话首条。该提醒同时携带当日日期段。
- **F28**：注入内容仅为摘要级——每条笔记只暴露标识、类型、描述三段。模型若要看全文，仍走文件读取工具按路径访问对应笔记。

#### 笔记提取- **F29**：触发时机：Agent 自然完成一轮后触发回调。回调内：
  - 若客户端未就绪，跳过；
  - 用互斥标志防止并发提取；
  - 自上一次提取后没有足够新增内容时跳过；
  - 截取最近若干条消息序列化为按角色分行的多行串作为输入，过滤掉过短的行；
  - 启动后台任务，结束后回填游标、把保存的笔记标识以系统消息回显。
- **F30**：提取器内部的合并策略：
  - 已有任务在运行时，把当前对话上下文暂存为"待运行"后立即返回空结果；
  - 当前提取完成时若有待运行上下文，自动用最新上下文做一次尾部运行；
  - 多次并发请求合并为一次尾部运行，避免抖动。
- **F31**：实际提取动作构造一个独立的会话管理器，把提取指令模板和会话摘要拼到一条用户消息里发给模型；指令要求模型按固定格式输出多个块，块之间用分隔线分割；当模型输出"无可记录"占位符或缺少必要标识字段时静默返回空结果。
- **F32**：解析后逐块提取字段（标识、类型、描述、正文），缺少标识或正文的块丢弃；其余按类型路由到对应目录写入 Markdown 文件，frontmatter 顶层带标识、描述、类型三段，正文写在 frontmatter 之后。
- **F33**：成功写入任何笔记后立即重建索引；提取或写入失败静默吞掉，不影响主会话。

### 第 4 层：辅助—按需的相关记忆检索- **F34**：记忆管理器对外提供"按查询找相关笔记"的能力：扫描两级目录拿到笔记元数据列表（按修改时间倒序，封顶若干条），过滤掉已经被注入过的；把候选打包成清单文本（含作用域、类型、路径、修改时间、描述），连同选择器系统提示一起塞到一条用户消息发给模型；解析模型返回的结构化结果，最多取若干个；选择器失败统一返回空结果。
- **F35**：按需检索与背景索引解耦：前者按需触发、给具体查询用；后者全局注入、给模型大局观。

### 集成与生命周期- **F36**：系统提示组装函数接受可选的"自定义指令"与"记忆段落"两段：非空时分别加入对应分区并赋予合适的优先级；本章默认走会话层的一次性注入，组装函数的可选参数保留给未来直接走提示注入的场景。
- **F37**：会话层的注入动作是幂等的：通过标志保证每个会话管理器实例只注入一次；恢复会话时新建的会话管理器会重新注入当时的新鲜内容。
- **F38**：恢复动作与 Agent 主循环的互斥由 TUI 状态机自然实现：流式输出期间用户提交路径会先中断当前流，恢复命令在同步槽位处理，发生在用户主动调用时刻；当前未提供"运行中拒绝恢复"的硬阻塞，因为中断加同步替换已覆盖大多数实际场景。
- **F39**：笔记提取与用户主动压缩可并发：提取只读会话快照、只写记忆目录，不修改会话本身。

## 非功能需求- **N1（性能）**：项目指令加载（含内联引用展开）必须在 200ms 内完成。单次消息追加写入不超过 10ms。50 个会话的列表扫描不超过 500ms。
- **N2（并发安全）**：互斥标志防止两次提取并行；提取器内部的待运行队列将抖动期间的多次请求合并为一次尾部运行。追加写入是单次原子调用，无需额外锁。
- **N3（向后兼容）**：旧会话存档（无压缩边界、无类型字段）走全量重放分支，行为不变；没有任何项目指令文件时加载函数返回空串、不报错；记忆目录不存在时摘要返回空、索引重建仅在写入时按需创建目录。
- **N4（可测性）**：内联引用展开、会话存档解析与重建、记忆索引拼接、提取流程均可脱离真实大模型单测——以 Mock 客户端方式覆盖关键路径。
- **N5（错误隔离）**：指令文件读取失败降级为空；存档写入失败不会中断对话（最差是该行没落盘）；笔记提取错误被吞掉。清理动作的单个文件失败不影响其他文件。

## 不做的事- **不做向量数据库或检索增强**：记忆通过摘要索引一次性注入对话首条系统提醒；按需查询走选择器让模型自己挑。
- **不做团队记忆同步**：笔记只在本机存储和读取。
- **不做启动时自动恢复最近会话**：启动永远开新会话 ID，只通过显式恢复命令手动恢复。
- **不做会话合并**：每个会话存档独立。
- **不做记忆质量反馈回流**：提取指令模板固定，不做 A/B 或用户评分。
- **不做指令文件热更新**：初始化阶段加载一次，运行期间不监听文件变化。
- **不做笔记全文搜索**：模型通过摘要索引感知，要看全文走文件读取工具按路径访问。
- **不做基于时间戳前缀的清理**：清理依据是存档最后修改时间，与会话 ID 编码无关；这保证刚刚恢复过的旧会话不会被错误清理。

## 验收标准### 项目指令- **AC1（多层加载）**：在用户全局目录、仓库根目录、工作目录本地覆盖文件各放一份不同内容 → 对话首条系统提醒中包含三份内容，按"用户全局 → 仓库根 → 本地覆盖"顺序排列（越靠后优先级越高）。
- **AC2（缺失文件静默）**：只放工作目录下的项目指令文件 → 加载函数返回该文件包装后的内容，不报错。
- **AC3（内联引用展开）**：项目指令文件中写一行相对路径引用 → 内容替换该行，前面插入标注来源的注释行。
- **AC4（深度上限）**：构造 6 层嵌套引用链 → 第 6 层保留原文不展开，递归静默返回不抛错。
- **AC5（循环检测）**：A 引用 B、B 引用 A → 第二次引用保留原行不展开。
- **AC6（代码块跳过）**：项目指令文件中在围栏代码块内写一行同形态引用 → 该行原样保留、不触发文件读取。

### 会话存档- **AC7（会话 ID 格式）**：启动进程 → 当前会话 ID 形如"按 36 进制编码的毫秒时间戳"加"短随机十六进制后缀"，对应存档在第一次消息写入后被创建。
- **AC8（存档写入）**：发送一条消息、得到回复 → 存档包含至少两行（用户 + 助手），每行可解析为合法 JSON，包含角色、正文、时间戳字段。
- **AC9（压缩边界）**：触发一次压缩 → 存档中出现一行类型为"压缩边界"、正文为"摘要加保留尾部"结构化数据的记录。
- **AC10（崩溃容错）**：在存档中插入一行非法 JSON，再插入一行内容为空串的正常 JSON → 读取动作跳过两者，其他消息正常加载。

### 会话恢复- **AC11（恢复列表）**：输入恢复命令不带参数 → TUI 输出最多若干条历史会话，每条形如"会话 ID（消息数）— 首条用户消息"。
- **AC12（按 ID 恢复）**：输入恢复命令带 ID → 新建会话管理器、注入指令和记忆、按重建消息序列回放、切换当前会话 ID；TUI 末尾追加已恢复标注。
- **AC13（首条标题）**：会话信息中的标题是存档中第一条用户消息且正文非空的前若干字符。
- **AC14（边界重建）**：会话含一条压缩边界 → 重建后的第一条是摘要包装后的中文用户消息（含"本次会话延续自之前的对话"），随后是保留尾部内容，最后是边界之后的消息；边界之前的原始消息不出现。
- **AC15（旧会话兼容）**：会话不含压缩边界 → 重建动作全量重放每一条用户/助手消息。
- **AC16（恢复后追加）**：恢复后发新消息 → 存档行数递增，新消息追加到同一文件。

### 会话清理- **AC17（过期清理）**：手动把某个存档的最后修改时间设为超过过期阈值的过去时刻 → 调用清理动作后该文件被删除，返回值至少为 1。
- **AC18（新会话不被清理）**：刚创建的存档 → 清理动作执行后仍存在。

### 自动笔记- **AC19（提取触发）**：对话中说"以后回复都用简体中文" → Agent 一轮结束触发提取 → mock 模型返回带标识、类型为用户偏好的块 → 用户全局记忆目录下出现该笔记文件，frontmatter 顶层包含标识、描述、类型。
- **AC20（双路路由）**：mock 模型返回项目知识与参考资料各一块 → 文件落在项目级目录；用户偏好与纠正反馈块 → 文件落在用户全局目录。
- **AC21（占位符静默）**：mock 模型返回"无可记录"占位符 → 提取动作返回空结果，目录无新增。
- **AC22（索引重建）**：写入新笔记后 → 项目级目录下的索引文件被重写，按标识字母序列出两级目录所有笔记的列表行。
- **AC23（合并策略）**：当提取正在进行时再次调用提取并传入新上下文 → 立即返回空结果，当前提取结束后用新上下文自动执行一次尾部运行。

### 集成- **AC24（系统提示注入）**：初始化时先调注入动作再追加身份系统提醒 → 对话首条消息是合并后的系统提醒，包含项目指令段、自动记忆段、当日日期段。
- **AC25（幂等）**：同一个会话管理器实例上重复调用注入动作 → 仅注入一次。
- **AC26（端到端崩溃恢复）**：对话几轮 → 杀掉进程 → 重启 → 恢复列表中含该会话 ID → 按 ID 恢复 → 后续消息追加在同一文件。
