# MewCode Tool System Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为。验收时在复选框后记录实际证据。

## 实现完整性

- [x] **AC1：统一工具清单** — 启动工具工厂后恰好列出 `read_file`、`write_file`、`edit_file`、`run_command`、`find_files`、`search_code` 六个工具；每个工具的名称、描述、参数 Schema 和执行入口均非空且唯一。（验证：运行 Registry/factory 测试）
- [x] **AC2：注册中心行为** — 已注册工具可按名称取得，未知名称返回 `TOOL_NOT_FOUND`，重复名称注册失败。（验证：运行 `src/tool/registry.test.ts`）
- [x] **AC3：双协议工具描述** — Anthropic 和 OpenAI 请求中都包含六个工具，且名称、描述和参数约束与统一定义一致。（验证：运行两个 Provider 的请求映射测试并检查捕获的请求 JSON）
- [x] **AC4：项目路径边界** — 绝对路径、`..` 越界路径和解析到项目外的符号链接均被拒绝，项目外文件没有变化。（验证：运行 PathGuard 和文件工具边界测试）
- [x] **AC5：读取文件** — 项目内 UTF-8 普通文件可读；不存在路径、目录、非文本文件和越界路径返回可区分的结构化错误。（验证：运行 `read_file` 工具测试）
- [x] **AC6：写入文件** — 嵌套新路径会创建父目录；再次写入会覆盖旧内容；结果包含相对路径和写入量。（验证：运行 `write_file` 工具测试并读取 fixture 对比）
- [x] **AC7：唯一匹配编辑** — 原文出现一次时替换成功；出现零次或多次时不修改文件，分别返回未匹配和匹配不唯一错误。（验证：运行 `edit_file` 三种匹配场景测试）
- [x] **AC8：命令执行结果** — 成功命令返回 stdout 和退出码 `0`；失败命令返回 stderr 和非零退出码；超时命令被终止并标记超时，进程可继续工作。（验证：运行命令工具测试并确认无遗留子进程）
- [x] **AC9：文件模式查找** — glob 只返回项目内符合条件的相对路径，结果稳定排序，忽略指定目录且不跟随目录符号链接。（验证：运行 `find_files` fixture 测试）
- [x] **AC10：代码内容搜索** — 文本和正则搜索返回正确路径、行号和匹配行；无匹配返回成功空结果。（验证：运行 `search_code` 文本、正则和空结果测试）
- [x] **AC11：参数与执行错误隔离** — 六个工具的缺失字段、错误类型和非法值都返回结构化参数错误，不产生副作用且进程不退出。（验证：运行 Registry Schema 测试及六工具非法参数测试）
- [x] **AC12：OpenAI 流式参数聚合** — 名称和 JSON 参数拆分到多个 OpenAI SSE 事件后，只产生一次完整 `tool_call`，名称和参数正确。（验证：运行 `src/provider/openai.test.ts`）
- [x] **AC13：Anthropic 流式参数聚合** — 输入 JSON 拆分到多个 Anthropic SSE 事件后，只产生一次完整 `tool_call`，ID、名称和参数正确。（验证：运行 `src/provider/anthropic.test.ts`）
- [x] **AC14：工具结果回灌与最终回复** — 工具调用和结果以匹配 ID 进入历史，第二次模型请求能基于结果生成最终文本。（验证：运行 `src/chat/manager.test.ts` 单工具闭环场景）
- [x] **AC15：单工具边界** — 同一响应请求多个工具时全部不执行并显示限制提示；回灌后再次请求工具时也不执行。（验证：运行 ChatManager 多工具和二次工具调用测试）
- [x] **AC16：输出截断** — 文件、命令和搜索超出统一上限时结果不超过限制，并明确标记截断状态。（验证：运行输出限制和大结果工具测试）
- [x] **AC17：纯聊天回归** — 无工具调用时文本流、Thinking、多轮历史及 `/help`、`/clear`、`/exit` 行为保持正常。（验证：运行 ChatManager 回归测试并启动 TUI 手工操作命令）
- [x] **AC18：独立自动化验证** — 工具、Registry、路径、超时、双协议解析和单工具闭环可在无真实 API、无交互终端下自动验证。（验证：运行 `pnpm test`，确认测试使用假 fetch/Fake Provider）
- [ ] **AC19：平台验证** — 类型检查和自动化测试在 macOS 通过；实现未引入 Windows 专用命令或路径语义，并记录 Linux 运行结果。（验证：运行 `pnpm check`，在目标平台执行测试；当前证据：macOS 已通过，Linux 尚未执行）

## 集成验证

- [x] **启动根目录链路** — 入口使用当前启动目录创建 Registry，所有文件类工具共享同一根目录。（验证：从临时项目目录启动并检查工具返回的相对路径）
- [x] **工具工厂链路** — `createCoreToolRegistry()` 注册六个工具，Registry 定义可以直接传给 Provider。（验证：运行工厂测试并检查六个 Schema 可编译）
- [x] **Registry 到 Tool 链路** — Provider 给出的工具名和参数经 Registry 查找、Schema 校验后才执行具体工具。（验证：使用假工具记录执行次数和收到的参数）
- [x] **Provider 到 Chat 链路** — OpenAI/Anthropic 的 `tool_call` 事件都能被 ChatManager 收集为统一 ToolCall。（验证：两个 Provider 测试接入 Fake ChatManager）
- [x] **Chat 到 Provider 链路** — 单工具场景第一次请求带六个工具，第二次请求工具列表为空。（验证：Fake Provider 记录两次请求参数）
- [x] **结果回灌链路** — 成功和失败 ToolResult 都进入正确的 tool 消息，模型最终能收到合法 JSON 结果。（验证：检查 ChatManager 历史和两种协议请求体）
- [x] **纯文本旁路** — 模型不调用工具时不触发 Registry，现有流式回调仍逐 token 更新 UI。（验证：Fake Provider 纯文本测试并观察 TUI）

## 编译与测试

- [x] **类型检查** — 项目无 TypeScript 编译错误。（验证：运行 `pnpm typecheck`）
- [x] **自动化测试** — Tool、Registry、Provider 和 ChatManager 测试全部通过。（验证：运行 `pnpm test`）
- [x] **统一检查脚本** — 类型检查和测试可由一个脚本顺序完成。（验证：运行 `pnpm check`）
- [x] **无真实网络依赖** — 自动化测试不调用真实 LLM API、不依赖 API key 或交互式终端。（验证：在无 API key、网络关闭条件下运行 `pnpm test`）
- [x] **启动行为** — 应用可以正常进入 TUI；配置错误或缺少配置时显示明确错误而不是未捕获堆栈。（验证：运行 `pnpm start` 及一个无效配置场景）

## 端到端场景

- [x] **场景 1：读取项目文件** — 启动 MewCode，模型请求读取项目内文件，工具返回真实内容，最终回复引用该内容。（验证：使用 Fake Provider 运行单工具闭环测试）
- [x] **场景 2：写入并精确修改文件** — 模型先写入嵌套文件，再用唯一原文替换修改；最终文件内容与预期一致。（验证：临时项目目录端到端测试）
- [x] **场景 3：工具失败后恢复** — 模型请求不存在文件或非唯一编辑，错误结果回灌后生成解释；下一条用户消息仍可正常处理。（验证：Fake Provider + Registry 连续两轮测试）
- [x] **场景 4：命令结果闭环** — 模型执行项目根目录下的非交互命令，收到 stdout/退出码；失败或超时也不会退出 MewCode。（验证：命令工具测试和 ChatManager 错误回灌测试）
- [x] **场景 5：路径安全** — 模型请求绝对路径、`../` 路径和项目外符号链接时均被拒绝，项目外文件无变化。（验证：临时目录边界场景测试）
- [x] **场景 6：多工具限制** — 模型一次返回多个工具调用时没有任何工具执行并显示限制提示；后续普通消息仍可继续。（验证：Fake Provider 多工具场景测试）
- [x] **场景 7：纯聊天回归** — 启动后输入普通问题，模型不调用工具时仍能流式回复；`/help`、`/clear` 和 `/exit` 仍按原行为工作。（验证：tmux 或交互式终端手工验收）
