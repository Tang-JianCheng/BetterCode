# MewCode Tool System Spec

## 背景

当前 MewCode 已经能够通过终端界面与大模型进行流式多轮对话，但模型只能生成文字，无法观察或修改用户的项目。要让 MewCode 成为真正的编程 Agent，需要建立一套工具系统：模型声明想使用的工具及参数，MewCode 执行工具，再将结构化结果返回给模型。

本章聚焦工具系统的基础能力和单次工具调用闭环，不实现多轮自动规划。

## 目标

- 让模型能够请求读取文件、写入文件、修改文件、执行命令、查找文件和搜索代码内容。
- 为所有工具提供统一的名称、描述、参数 Schema 和执行行为。
- 让工具可以集中注册、按名称查找，并转换为当前 LLM API 支持的工具描述。
- 为工具执行提供统一的超时、异常捕获和结构化错误结果。
- 支持流式响应中的工具调用参数碎片拼接。
- 执行工具后把结果加入对话历史，使模型能够基于结果生成当前轮的最终回复。
- 将文件和命令操作限制在 MewCode 启动时确定的项目根目录内。

## 功能需求

- **F1：项目根目录上下文**  
  MewCode 启动时确定项目根目录。所有文件、编辑和搜索操作都以该目录为边界，拒绝绝对路径、路径穿越以及解析后落在根目录外的路径。

- **F2：统一工具契约**  
  每个工具都必须提供唯一名称、用途描述、参数 Schema 和执行能力。调用方不需要了解具体工具的内部实现。

- **F3：工具注册中心**  
  系统集中登记可用工具，支持按名称查找、列出全部工具，并拒绝名称重复的注册。

- **F4：LLM 工具描述转换**  
  注册中心中的工具可以转换为当前模型 API 能识别的工具列表，同时保持统一工具定义不依赖具体模型供应商。

- **F5：读取文件**  
  模型可以使用项目根目录内的相对路径读取文本文件。成功时返回文件内容；文件不存在、不是普通文件、无法读取或路径越界时返回明确错误。

- **F6：写入文件**  
  模型可以创建新文件或用完整内容覆盖已有文件。目标必须位于项目根目录内；父目录不存在时自动创建。成功结果应说明写入目标和写入量。

- **F7：精确修改文件**  
  模型可以提交目标文件、原文和替换文本。只有原文在文件中恰好出现一次时才执行替换；出现零次或多次时不修改文件，并返回可供模型调整的明确错误。

- **F8：执行命令**  
  模型可以执行非交互式命令。命令固定从项目根目录启动，调用方不能指定其他工作目录。结果包含标准输出、标准错误、退出码以及是否超时。该约束不构成操作系统级沙箱，命令仍具有当前 MewCode 进程的系统权限。

- **F9：按模式查找文件**  
  模型可以使用模式查找项目内的文件和目录。结果使用相对项目根目录的路径表示，并保持确定、可重复的排序。

- **F10：搜索代码内容**  
  模型可以在项目内按文本或正则模式搜索文件内容。结果至少包含相对文件路径、行号和匹配行；无匹配时返回成功的空结果，而不是错误。

- **F11：统一执行保护**  
  所有工具调用都经过参数校验、超时控制和异常捕获。工具失败不得导致主程序崩溃，必须转换为结构化结果，区分成功、参数错误、路径错误、超时和执行错误。

- **F12：流式工具调用解析**  
  LLM 客户端能够识别流式响应中的工具调用，按调用标识聚合分散到多个事件中的名称和 JSON 参数片段，并仅在参数完整后交给工具执行层。

- **F13：工具结果回灌**  
  工具调用及其结构化结果必须以对应模型协议要求的消息格式加入对话历史，确保模型能够理解调用与结果的关联。

- **F14：单次工具调用闭环**  
  每次用户提问最多执行一个工具。模型发起工具调用后，MewCode 执行该工具并把结果回灌，再请求模型生成当前轮最终回复。若后续响应再次请求工具，本阶段不继续执行，并给出明确的限制提示。

## 非功能需求

- **N1：稳定性**  
  任意工具的参数错误、文件系统异常、命令失败、超时或返回内容异常，都不得导致 MewCode 主进程崩溃或破坏后续对话。

- **N2：协议兼容性**  
  工具调用闭环必须同时支持现有 Anthropic 协议和 OpenAI 兼容协议，包括 DeepSeek；上层工具定义和执行逻辑不得依赖某个供应商。

- **N3：向后兼容性**  
  当模型没有调用工具时，现有的流式文本、Thinking 展示、多轮历史以及命令功能应保持原有行为。

- **N4：响应开销**  
  除工具本身的文件访问或命令执行时间外，参数解析、注册中心查找和结果封装不应造成可感知的终端卡顿。

- **N5：输出控制**  
  文件内容、搜索结果和命令输出必须有统一的大小限制，防止超大结果耗尽内存或模型上下文。发生截断时，结果必须明确标记已截断，不能伪装成完整输出。

- **N6：确定性**  
  相同项目状态下，文件查找和代码搜索结果应使用稳定排序；精确编辑不得在匹配不唯一时猜测目标。

- **N7：文本范围**  
  本阶段的文件读取、写入、编辑和内容搜索以 UTF-8 文本为目标。遇到无法按文本处理的内容时返回明确错误，不静默损坏文件。

- **N8：可测试性**  
  六个工具、注册中心、路径边界、超时封装和流式参数聚合都应能独立测试，不依赖真实 LLM API 或交互式终端。

- **N9：平台范围**  
  支持当前项目目标平台 macOS 和 Linux；不要求本阶段兼容 Windows 命令执行语义。

## 不做的事

- 不实现自动 Agent Loop；一次工具结果回灌后只生成当前轮最终回复。
- 不执行一轮中的多个工具调用，不支持并行工具调用或工具调用链。
- 不提供删除文件、移动文件、复制文件、目录管理等额外工具。
- 不实现模糊编辑、补丁应用或基于行号的智能合并；修改文件仅支持原文唯一匹配替换。
- 不提供操作前确认、权限审批或危险命令分级机制。
- 不提供容器、`chroot` 或其他操作系统级命令沙箱。
- 不限制命令可执行程序白名单，也不分析命令是否具有破坏性。
- 不处理二进制文件、图片、压缩包或非 UTF-8 文本编辑。
- 不实现工具调用记录持久化、会话恢复或跨会话任务继续。
- 不新增第三方 MCP 工具协议或远程工具接入。
- 不在本章实现工具调用专用的复杂 TUI，例如审批弹窗、调用时间线或可折叠结果面板。
- 不改变现有供应商选择、Markdown 渲染、流式中断、重新生成和多会话等其他功能范围。

## 验收标准

- **AC1：统一工具清单**  
  启动工具系统后，可以列出恰好六个核心工具；每个工具都有非空且唯一的名称、描述、参数 Schema 和可执行入口。（覆盖 F2、F3）

- **AC2：注册中心行为**  
  按已注册名称可以取得对应工具；查询未知名称返回结构化错误；注册重复名称时被明确拒绝。（覆盖 F3）

- **AC3：双协议工具描述**  
  使用 Anthropic 和 OpenAI 兼容 Provider 分别发起请求时，六个工具都以对应协议认可的结构出现在请求中，且名称、描述和参数约束保持一致。（覆盖 F4）

- **AC4：项目路径边界**  
  对绝对路径、包含 `..` 的越界路径，以及通过符号链接解析到项目外部的路径执行读取、写入、编辑或搜索时，操作被拒绝，项目外文件保持不变。（覆盖 F1）

- **AC5：读取文件**  
  读取项目内已知 UTF-8 文件时返回完整内容；读取不存在的文件、目录或非文本内容时返回可区分的结构化错误。（覆盖 F5）

- **AC6：写入文件**  
  写入不存在的嵌套路径时自动创建父目录和文件；再次写入同一路径时完整覆盖旧内容；返回结果包含目标路径和写入量。（覆盖 F6）

- **AC7：唯一匹配编辑**  
  原文恰好出现一次时只替换该处；原文不存在或出现多次时文件内容完全不变，并分别返回“未匹配”和“匹配不唯一”的错误。（覆盖 F7）

- **AC8：命令执行结果**  
  执行成功命令时返回标准输出和退出码 `0`；执行失败命令时返回标准错误和非零退出码；执行超时命令时终止该进程并返回超时标记，MewCode 保持可继续使用。（覆盖 F8、F11）

- **AC9：文件模式查找**  
  在固定测试目录中按模式查找时只返回符合条件的项目内路径，路径均相对项目根目录，并按稳定顺序排列。（覆盖 F9）

- **AC10：代码内容搜索**  
  搜索已知文本或正则模式时，结果包含正确的相对路径、行号和匹配行；无匹配时返回成功的空结果。（覆盖 F10）

- **AC11：参数与执行错误隔离**  
  对六个工具分别提交缺失字段、错误类型或非法值时，每次都返回结构化参数错误，不执行副作用且不导致进程退出。（覆盖 F11）

- **AC12：OpenAI 流式参数聚合**  
  模拟一个工具名称和 JSON 参数被拆分到多个 OpenAI 流式事件中的响应，最终只产生一次工具调用，调用名称和解析后的参数与原始完整数据一致。（覆盖 F12）

- **AC13：Anthropic 流式参数聚合**  
  模拟一个工具输入 JSON 被拆分到多个 Anthropic 流式事件中的响应，最终只产生一次工具调用，调用标识、名称和参数保持完整。（覆盖 F12）

- **AC14：工具结果回灌与最终回复**  
  用户提出需要读取项目文件的问题后，模型发起一次读取调用；工具结果以匹配的调用标识加入历史；模型随后基于真实文件内容生成最终文本回复。（覆盖 F13、F14）

- **AC15：单工具边界**  
  单个响应同时请求多个工具时不执行其中任何一个，并给出明确的本阶段限制提示；工具结果回灌后的模型响应再次请求工具时也不继续执行。（覆盖 F14）

- **AC16：输出截断**  
  当文件、命令或搜索结果超过统一输出上限时，返回内容处于限制范围内，并明确包含截断状态和原始结果超限的信息。（覆盖 N5）

- **AC17：纯聊天回归**  
  模型不请求工具时，普通文本仍能流式显示，Thinking 内容仍按现有方式展示，多轮历史和 `/help`、`/clear`、`/exit` 行为不变。（覆盖 N2、N3）

- **AC18：独立自动化验证**  
  在不调用真实 LLM API、不启动交互式终端的情况下，可以自动验证六个工具、注册中心、路径边界、超时、双协议流式解析和单工具闭环。（覆盖 N1、N6、N8）

- **AC19：平台验证**  
  类型检查和自动化测试在目标 macOS 环境通过；实现不依赖仅 Windows 可用的路径或命令语义，并具备在 Linux 上运行的明确兼容边界。（覆盖 N9）
