# BetterCode 终端 Markdown 渲染 Spec

## 背景

BetterCode 的助手回复目前以纯文本展示，模型输出的 Markdown 标记（标题、粗体、行内代码、代码块、列表、链接等）会原样出现在终端里，可读性差。用户希望模型完整输出一次后，正文按 Markdown 渲染一次，呈现形式接近日常 AI 回复：有标题层级、强调、代码块、列表和链接，而不是让用户看到原始 `**`、`` ` `` 和 ``` ``` ``` 标记。

现有 UI 已经具备展示契约、终端能力、官方主题、结构化命令面板和流式正文区域。本次在保留这些能力的前提下，为“模型最终回复”增加独立于渲染框架的 Markdown 解析与终端渲染链路。

## 目标

- G1：模型最终回复按常见 Markdown 渲染，正文不再裸露原始标记。
- G2：流式输出期间仍显示纯文本，流结束后对该条回复只解析渲染一次。
- G3：渲染只改变展示，原始 Markdown 文本始终完整保留，会话恢复和回滚不丢原文。
- G4：支持标题、段落、粗斜体、删除线、行内代码、代码块、列表、引用、链接、图片占位和表格。
- G5：支持 full、compact、narrow 三种终端宽度，以及 ASCII、无颜色和低动态降级。
- G6：渲染安全：不执行 HTML、不加载外部资源、不把模型内容当作终端控制序列。
- G7：不改变现有用户消息、本地命令面板、通知、权限、Agent Loop 和快捷键行为。

## 功能需求

### F1：最终回复一次性渲染

Agent 流结束后，界面拿到完整 `finalText`，对该条正文解析一次 Markdown，并把解析结果与原文一起进入历史。流式过程中出现的部分文本不参与 Markdown 解析，继续按纯文本显示。

同一历史项在后续每次重绘时直接复用已解析结果，不得重复解析。

### F2：块级语法

支持以下块级元素：

- ATX 标题：`#` 到 `######`。
- 段落与多行正文。
- 围栏代码块和缩进代码块；代码块保留原始缩进与空行，并显示可选语言标识。
- 无序列表、有序列表及嵌套列表。
- 引用块及嵌套引用。
- 分隔线。
- GFM 表格。

不支持或无法安全展示的块（例如原始 HTML）以文字形式安全展示，不解释标签、不执行脚本。

### F3：行内语法

支持以下行内元素：

- 粗体、斜体、删除线。
- 行内代码。
- 链接：展示链接文本和弱化后的 URL。
- 图片：展示 `[alt](url)` 文本占位，不加载图片协议。
- 转义字符与段落内换行。

### F4：代码块展示

代码块使用与正文明确区分的视觉样式。语言标识以弱化文字显示；代码内容逐行保留缩进。超长代码行按终端宽度安全处理，不产生横向溢出，也不破坏 Agent 流程。

### F5：表格展示

full 和 compact 宽度使用紧凑表格布局；narrow 宽度降级为逐项键值行，保证列不重叠、不越界。

### F6：降级与可读性

无颜色模式不依赖颜色表达粗体、代码和链接；ASCII 模式不输出 Unicode 装饰；低动态模式不增加动画。所有关键语义必须有文字或符号兜底。

### F7：历史与恢复

当前会话中助手最终回复按 Markdown 渲染；恢复历史会话或回滚对话时，助手消息同样按 Markdown 渲染。用户消息始终按纯文本展示，不被 Markdown 化。

### F8：解析失败兜底

解析或渲染异常时，该条助手回复回退为原始纯文本并附带受控错误提示，不让 UI 崩溃，也不阻塞后续输入与退出。

## 非功能需求

- N1：一条助手回复在流结束后只解析一次；解析结果存放在展示模型中，不依赖每次渲染重新计算。
- N2：所有渲染行的显示宽度不超过可用宽度，中文和组合字符按终端宽度处理。
- N3：Markdown 解析与渲染逻辑不依赖 React、Ink 或终端颜色实现。
- N4：新增依赖使用成熟 Markdown 解析库，不手写一套完整解析器。
- N5：模型内容中的 HTML、脚本和原始 ANSI 控制序列不得被解释或执行。
- N6：现有 440 项测试、命令语义、权限流程、会话恢复、快捷键和 UI 降级行为不得回归。
- N7：新增源码注释与 Git 提交信息使用中文，产品名称统一为 BetterCode。

## 不做的事

- 不做流式增量 Markdown 渲染；实时输出继续使用纯文本。
- 不渲染图片协议、Sixel、Kitty Graphics、LaTeX 或 iframe。
- 不执行或解释模型返回的 HTML。
- 不修改会话持久化、上下文压缩和消息存储的原始文本格式。
- 不把用户消息、本地命令结果、通知和交互面板改成 Markdown 自由解析。
- 不新增 Markdown 编辑器、预览窗格、主题市场或自定义主题。
- 不重写完整 Markdown 解析器，复用成熟解析库。

## 验收标准

- AC1：包含标题、粗体、行内代码、代码块、列表、引用、链接和表格的模型回复，在流结束后以 Markdown 形式渲染一次；流式期间保持纯文本。
- AC2：同一历史项重绘时解析次数不增加；解析结果与原文一起保存在展示模型中。
- AC3：120、80、55 列下渲染行均不越界；narrow 表格降级为键值行。
- AC4：`NO_COLOR`、ASCII 和低动态模式下粗体、代码、链接和标题仍可辨认。
- AC5：含 `<script>`、`<img onerror>` 或 ANSI 转义的模型正文只作为普通文字展示，不执行、不解释、不触发网络。
- AC6：解析失败时回退纯文本并显示受控提示，Agent、输入和退出流程不受影响。
- AC7：恢复会话和回滚后的助手消息按 Markdown 渲染，用户消息保持纯文本。
- AC8：`pnpm check`、UI 专项测试、静态扫描和 `git diff --check` 全部通过。

## 增量修订：渲染体验第二轮（2026-08-03）

### 背景

第一轮 Markdown 渲染落地后，实际对话样例（如 Context7/Redis 文档）仍显得不够精致：表格列宽被平均撑开、外侧竖线和整行分隔线过重、行内代码里的 `|` 被 GFM 表格拆列、标题仍暴露 `#` 标记。本轮在不改渲染链路与历史契约的前提下做展示层打磨。

### 增量需求

- F9：宽屏表格按内容自适应列宽（保留 88 列上限），去掉外侧竖线与尾部空白，分隔线长度跟随表宽。
- F10：表格单元格与列表项内的行内代码正确渲染；代码内的 `|` 不再被当作表格列分隔符。
- F11：标题不再输出 `#` 标记，彩色模式用主题色加粗表达层级；原文仍完整保留。
- F12：块之间增加一个空行间距，分隔线缩短为最多 28 列，避免整屏横线。
- F13：命令面板等结构化表格同步使用自适应列宽。

### 验收增量

- AC9：包含代码内 `|` 的表格在宽屏/紧凑/窄屏下列数正确、无外侧边框、无尾随空白。
- AC10：标题在有颜色与无颜色模式都不输出 `#` 标记；正文语义靠样式或文字兜底。
- AC11：`pnpm typecheck`、Markdown/UI 专项测试与全量测试通过；`git diff --check` 无冲突标记。

## 增量修订：统一来源渲染（2026-08-03）

### 背景

实际使用中 `/help` 等命令面板仍以旧式竖线/边框表格展示，与助手最终回复的 Markdown 渲染风格不统一。用户希望无论内容来自模型、命令面板还是通知，在展示给用户之前都统一走一次 Markdown 渲染，去掉 `╭─/╰` 边框和原始竖线表格。

### 增量需求

- F14：所有展示来源（模型最终回复、命令面板、通知等）在展示前统一转为 Markdown AST，由 `MarkdownView` 渲染。
- F15：命令面板分组标题改为 Markdown 标题，不再输出 `╭─ [HELP] 命令目录` 和 `│` 边框。
- F16：结构化块（text、key_value、table、list、divider）可转换为 Markdown 块；`key_value` 渲染为列表项，表格沿用 Markdown 表格。
- F17：通知正文与详情同样走 Markdown 渲染，保留首行语气标签与标题。
- F18：渲染只影响展示，原始 `PresentationBlock` 结构仍保留，供纯文本命令回显等场景使用。

### 验收增量

- AC12：`/help` 在 120/80/55 列下均不出现 `╭`、`╰` 或旧式 `│` 边框，标题和表格与助手回复一致。
- AC13：命令文档与通知内容均可由 `MarkdownView` 渲染，宽度约束和 ASCII/无颜色降级保持有效。
- AC14：`pnpm typecheck`、Markdown/UI 专项测试与全量测试通过；`git diff --check` 无冲突标记。

## 增量：不再渲染思考内容

- F19：`MarkdownView` 删除 `thinking` 入参与思考分区渲染，只渲染正文 Markdown AST。
- F20：`ConversationPresentation` 删除 `thinking` 字段，最终助手消息不再携带思考文本。

### 验收增量

- AC15：无论模型是否返回 `thinking_delta`，Markdown 渲染只输出正文，无 `┊` 思考行。
