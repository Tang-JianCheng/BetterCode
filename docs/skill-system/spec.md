# BetterCode Skill 系统 Spec

## 背景

BetterCode 已具备 Agent Loop、工具注册中心、运行期指令注入、上下文管理和斜杠命令系统，但可复用 AI 操作仍需用户反复输入完整提示词。现有工具通常按 Agent 模式整体暴露，无法针对某个工作流收窄可见工具，也缺少按需加载 SOP 和专属工具的能力。

Skill 系统把可复用操作封装成带 YAML frontmatter 的 Markdown 文件。启动时模型只看到 Skill 名称和一句说明；真正使用时，系统才加载完整 SOP、参数和专属工具，从而减少上下文成本并提高工具选择准确率。

## 目标

- G1：支持项目级、用户级、内置三级 Skill 发现与确定性覆盖。
- G2：实现元信息发现和完整能力激活两阶段加载。
- G3：共享模式支持多个 Skill 持续激活，完整指令每轮置顶注入。
- G4：独立模式在临时对话中一次性运行，只向主历史回流结果摘要。
- G5：通过工具白名单收窄 Agent 可见工具，同时始终保留系统加载工具。
- G6：目录型 Skill 可携带 Node.js 专属工具，并复用现有工具超时、权限和错误处理。
- G7：为 Skill 自动注册斜杠短命令，并在运行期间响应文件热更新。
- G8：提供 `commit`、`review`、`test` 三个内置样板 Skill。

## 功能需求

### Skill 定义与发现

- F1：单文件 Skill 和目录型 Skill 都以 Markdown 入口文件描述能力。入口文件由 YAML frontmatter 和非空 Markdown 正文组成，正文是激活后交给模型的 SOP。
- F2：frontmatter 包含唯一名称、一句话说明、可见工具白名单、执行模式；独立模式可配置携带的最近历史消息条数；可选模型字段引用 `config.yaml` 中的 Provider 配置名。
- F3：参数通过正文中的 `{{args}}` 占位符注入。没有参数时替换为空字符串；替换后的正文仍按外部内容处理，不能突破运行期指令消息边界。
- F4：Skill 来源优先级固定为项目级高于用户级高于内置级。项目级目录为 `<project>/.bettercode/skills`，用户级目录为 `~/.bettercode/skills`，内置目录随 BetterCode 分发。
- F5：同名 Skill 只保留最高优先级候选。若最高优先级候选解析失败，该名称被禁用并产生诊断，不回退到低优先级版本；其他名称继续正常加载。
- F6：支持 `<scope>/*.md` 单文件形式和 `<scope>/<name>/SKILL.md` 目录形式。目录型 Skill 的专属工具文件只能位于该 Skill 目录内。
- F7：名称、说明、模式、历史条数、模型引用、白名单和正文都要校验。语法或普通字段错误只禁用该 Skill；有效 Skill 的白名单引用不存在工具时，启动必须失败并指出 Skill 和工具名。
- F8：`model` 只允许用于独立模式，值必须匹配现有 Provider 配置名；共享模式沿用当前 Provider。

### 两阶段加载与激活

- F9：启动和每轮请求只向模型公开可用 Skill 的名称和一句说明，不注入未激活 Skill 的正文、白名单、脚本路径或其他内部元数据。
- F10：系统注册不受 Skill 白名单限制的 `load_skill` 工具。模型可按名称和参数激活 Skill；未知、禁用或加载失败以结构化工具错误返回，Agent Loop 不崩溃。
- F11：共享 Skill 激活后，其参数替换后的完整 SOP 在每轮运行期指令最前部注入，直到清空会话。再次激活同名 Skill 时更新该 Skill 的参数化指令，不重复创建条目。
- F12：多个共享 Skill 可以同时激活；其完整指令按首次激活顺序稳定排列，工具白名单取并集。
- F13：独立 Skill 不加入主会话激活列表。它在一次性临时对话中执行，结束后丢弃独立历史，只把最终结果摘要写回主对话。
- F14：独立 Skill 可携带主会话最近若干条完整消息组，默认 `0`。截取时不得拆开助手工具调用与对应工具结果；用户原始文本保持不变。
- F15：独立 Skill 使用 frontmatter 指定的 Provider；未指定时沿用当前 Provider。其最终回复被视为回流摘要，执行提示必须要求输出可独立理解的简洁结果。
- F16：`/clear` 清空主对话时同步清除全部共享 Skill 激活状态和参数化正文。

### 工具白名单与专属工具

- F17：没有共享 Skill 激活时，Agent 看见现有默认工具和 `load_skill`，但看不见任何未激活 Skill 的专属工具。
- F18：存在共享 Skill 时，Agent 只看见所有已激活 Skill 白名单的并集和 `load_skill`。Plan Mode 在此基础上继续移除副作用工具，不能被 Skill 放宽。
- F19：调度执行必须再次校验工具是否在当前可见集合中。模型猜中已注册但不可见的工具名时，返回结构化不可用结果，不得实际执行。
- F20：`load_skill` 是系统级工具，始终可见且不参与 Skill 白名单交集；它不需要人在回路确认，但仍受参数 Schema、取消和错误处理约束。
- F21：目录型 Skill 可在 `tools` 子目录中声明专属工具。每个工具由一个元信息文件、一个 JSON Schema 和一个 `.mjs` 实现脚本组成，名称必须在全局工具注册中心唯一。
- F22：专属工具脚本由 Node.js 子进程执行，项目根目录为工作目录。stdin 接收一次 JSON 参数，stdout 必须返回结构化工具结果，stderr 只作为有界诊断。
- F23：专属工具脚本路径和 Schema 路径必须解析真实路径并保持在所属 Skill 目录内，拒绝路径穿越、悬空链接和符号链接逃逸。
- F24：专属工具注册进现有 Tool 接口，复用参数校验、输出限制、超时、取消、权限和 Plan Mode 约束。脚本不通过 Shell 启动。

### 斜杠命令与热更新

- F25：每个可用 Skill 自动注册同名斜杠命令，命令说明来自 Skill 元信息，参数作为 `{{args}}` 输入。斜杠命令直接加载并运行，不再要求模型先选择 `load_skill`。
- F26：共享 Skill 斜杠命令先激活 Skill，再把本次任务送入主 Agent；独立 Skill 斜杠命令直接启动临时 Agent，并只向主历史提交命令文本和最终摘要。
- F27：Skill 名称与内置命令名称或别名冲突时启动失败。Skill 不声明命令别名，隐藏或禁用 Skill 不参与帮助和补全。
- F28：运行期间定期检测三级目录变化并原子重建 Skill 快照。有效更新刷新目录、命令、正文和专属工具；删除共享 Skill 时同步取消其激活状态。
- F29：热更新若出现解析错误、工具冲突、未知白名单或命令冲突，保留上一个完整有效快照并记录诊断，不让半成品状态进入正在运行的 Agent。
- F30：正在执行的 Agent 轮次使用启动该轮时的稳定 Skill 快照；更新从下一次 Agent 请求或命令补全开始生效。

### 内置样板

- F31：内置 `commit` Skill 使用共享模式，指导 Agent 检查差异、运行必要验证并生成中文 Git 提交信息。
- F32：内置 `review` Skill 使用独立模式，优先报告 bug、行为回归、安全风险和缺失测试，默认携带最近消息。
- F33：内置 `test` Skill 使用独立模式，根据参数选择最相关测试并报告失败原因，默认不携带主历史。
- F34：三个内置样板都由普通 Skill 文件定义，不在 TypeScript 中硬编码 SOP。现有 `/review` 固定提示词迁移为内置 Skill。

## 非功能需求

- N1：Skill 发现、覆盖和命令顺序稳定，同一文件集合在不同启动中产生相同目录顺序。
- N2：未激活正文和脚本内容不进入 Provider 请求；热更新期间也不能短暂泄漏低优先级或无效内容。
- N3：新增源码注释和 Git 提交信息使用中文，产品名称统一为 BetterCode。
- N4：测试不得读取真实用户 Skill 目录、调用真实模型 API 或执行仓库外脚本；所有用户目录、Provider 和脚本均可注入替身。
- N5：文件监听器、临时上下文和子进程在清空、取消和关闭时正确回收，不阻止 Node.js 进程退出。
- N6：Skill 系统不改变稳定 System Prompt 和工具描述的缓存策略；目录元信息和激活指令继续走运行期消息通道。
- N7：独立模式的详细工具历史不进入主会话存档、长期记忆提取或主会话上下文估算。

## 不做的事

- 不实现 Skill 市场、下载、发布、版本解析或自动升级。
- 不支持 Python、Shell、TypeScript 源码或任意可执行文件作为专属工具实现，只支持 Node.js `.mjs`。
- 不为专属脚本增加操作系统级沙箱、网络限制或资源配额；仍依赖现有权限层和进程权限边界。
- 不支持 Skill 自定义斜杠命令别名或覆盖 BetterCode 内置命令。
- 不支持独立 Skill 在完成后持续激活。
- 不让共享模式切换 Provider；指定模型仅适用于独立模式。
- 不实现 Skill 之间的依赖声明、版本约束或自动级联激活。

## 验收标准

- AC1：三级目录存在同名 Skill 时只选择项目级；项目级损坏时该名称禁用且不回退，其他 Skill 仍可用。
- AC2：首次请求只包含 Skill 名称和说明，不包含未激活正文；调用 `load_skill` 后下一轮运行期指令最前部出现完整参数化 SOP。
- AC3：两个共享 Skill 激活后，指令都持续注入，工具集合等于白名单并集加 `load_skill`；`/clear` 后恢复默认工具且激活列表为空。
- AC4：独立 Skill 只携带配置数量的最近完整消息组，使用指定 Provider，结束后主历史只增加命令和摘要，不包含子 Agent 工具消息。
- AC5：白名单引用未知工具时冷启动失败；猜测未授权但已注册工具时返回不可用且工具实现没有执行。
- AC6：未激活专属工具不出现在 Provider 工具列表；激活后可按 Schema 调用，超时、取消、非法输出和非零退出都返回结构化错误。
- AC7：专属工具路径穿越和符号链接逃逸被拒绝，项目外脚本不执行。
- AC8：`/commit`、`/review`、`/test` 出现在帮助和补全中，并按各自共享或独立模式直接执行。
- AC9：新增、修改或删除 Skill 后，下一次补全和 Agent 请求采用完整的新快照；无效热更新保留旧快照且当前任务不中断。
- AC10：Plan Mode 下即使白名单包含副作用工具也只暴露只读工具和 `load_skill`。
- AC11：指定不存在 Provider、无效 frontmatter、空正文或重复专属工具只影响对应 Skill 并产生清晰诊断，除明确要求启动失败的冲突外不阻断其他 Skill。
- AC12：类型检查、全量测试和差异检查全部通过，监听器和子进程测试结束后无悬挂句柄。

## 增量：/skill 动态命令面板

### 变更内容

- F：新增 `/skill` 命令（`type: ui`）与 `SkillDialog` 动态面板：列出全部可用 Skill（`/名称` 左对齐、`共享/独立 · 描述` 右对齐），Enter 运行选中的 Skill，Esc 退出；方向键选择并整行高亮，超一页显示剩余数量。

### 验收补充

- AC：`/skill` 列出全部 Skill，方向键选择、Enter 运行、Esc 退出；无 Skill 时给出提示。
