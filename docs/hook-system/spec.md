# BetterCode Hook 系统 Spec

## 背景

BetterCode 已具备 Agent Loop、工具系统、权限系统、上下文注入、命令系统和 Skill 系统，但格式化、外部通知、安全补充检查和环境上下文注入仍需要用户手动触发，或者由各模块以零散回调实现。随着生命周期节点增多，继续在 Chat、Agent 和 Tool 模块中硬编码自动化动作，会让触发条件、失败策略和执行边界难以统一维护。

本章为 BetterCode 增加声明式 Hook 系统。用户通过 YAML 以“事件 + 条件 + 动作”描述规则，BetterCode 在系统、会话、轮次、消息和工具生命周期的固定节点发布事件，由集中式 Hook 运行时完成条件匹配和动作执行。工具执行前 Hook 可以明确拒绝调用，并把原因作为结构化工具结果返回模型；其他 Hook 失败只记录日志，不改变 Agent 主流程结果。

## 目标

- 用统一、可验证的规则模型描述生命周期自动化，避免各模块重复实现触发和错误处理。
- 覆盖 BetterCode 的系统、会话、用户任务、消息和工具关键节点，并让事件触发边界可预测、可测试。
- 在工具权限判断和实际执行前提供可编程拦截点，使外部安全策略可以基于工具名称和结构化参数拒绝调用。
- 支持命令、提示词、HTTP 和子 Agent 四类动作，其中子 Agent 在本章只保留稳定配置契约和占位行为。
- 保证 Hook 配置错误在启动期暴露，运行期动作错误不会使 Agent Loop、会话或 BetterCode 进程崩溃。

## 功能需求

### F1：统一规则模型

每条 Hook 规则必须包含一个生命周期事件和一个动作，可以包含一个条件以及执行控制选项。条件缺失表示事件触发时无条件执行；事件或动作缺失时配置无效。

规则的事件、条件、动作和执行控制必须在启动阶段集中校验。未知字段、未知事件、无效条件、动作字段缺失、互斥选项并用或事件不支持对应执行控制时，BetterCode 必须拒绝启动并指出配置文件、规则位置和原因。

### F2：固定生命周期事件

首版支持以下事件：

- **系统级**：`system_start`、`system_stop`。
- **会话级**：`session_start`、`session_end`。
- **轮次级**：`turn_start`、`turn_end`。
- **消息级**：`user_message`、`assistant_message`。
- **工具级**：`pre_tool_use`、`post_tool_use`。

一次“轮次”指一条用户输入被接受后，到对应 Agent 运行以任意停止原因结束的完整过程，不等同于 Agent Loop 内部的单次模型请求。`assistant_message` 在模型产生一条完整助手消息后触发，包括带工具调用的中间消息；流式文本碎片不得重复触发消息事件。

BetterCode 启动时依次触发系统开始和首个会话开始。清空会话或恢复其他会话时，先结束旧会话，再开始新会话。正常退出时先结束当前会话，再触发系统停止。每个开始事件必须与对应结束事件最多配对一次，重复关闭不得重复触发。

### F3：结构化事件上下文

每次触发必须提供只读的结构化上下文，至少包含事件名称、项目根目录、会话标识和时间。不同层级按需增加以下数据：

- 轮次事件包含运行模式、用户任务和最终停止原因。
- 消息事件包含消息角色、完整文本，以及助手消息的工具调用摘要。
- 工具事件包含工具调用标识、工具名称和完整结构化参数；执行后事件还包含最终工具结果。
- 系统与会话事件包含可用的启动、关闭或切换原因。

条件和动作读取同一份事件快照。Hook 不得直接修改事件对象、对话历史或工具参数；需要影响模型时必须使用提示词动作，需要阻止工具时必须使用执行前动作的结构化拒绝结果。

### F4：条件表达式

条件由一组原子匹配组成，并且必须选择“全部满足”或“任一满足”其中一种组合方式，同一条件组不得混用两种逻辑，也不支持递归嵌套组合。条件省略表示无条件匹配。

每个原子匹配从事件上下文读取一个声明字段，并支持：

- 精确匹配。
- glob 匹配。
- 正则匹配。
- 对上述匹配结果取反。

匹配基础能力与权限规则共享，不复制两套 glob、精确值规范化和错误处理逻辑；现有权限 YAML 的外部语法和匹配行为保持兼容。正则必须在启动时编译，非法表达式使配置校验失败。字段不存在或值类型不支持匹配时，该原子条件视为不匹配，取反也不得把缺失字段变成命中。

对象和数组字段在匹配前使用稳定 JSON 表示，字符串、数字和布尔值使用确定性文本表示。`pre_tool_use` 必须能够直接匹配工具名称和工具参数中的具体字段，以支持命令、路径和其他参数级安全策略。

### F5：命令动作

命令动作在项目根目录下通过系统 Shell 执行固定命令，可读取事件上下文，并具有可配置超时。命令的 stdout、stderr 和退出状态必须有界收集，超时或取消后终止子进程，不得遗留后台句柄。

在 `pre_tool_use` 中，命令动作可以通过 stdout 返回结构化决定：`allow` 表示本条 Hook 不阻断，`deny` 表示拒绝工具调用并携带非空原因。只有成功解析出的明确 `deny` 可以阻断；非零退出、超时、无输出、非法 JSON 或非法决定都按 Hook 运行失败处理，记录日志后继续后续安全检查和 Agent 主流程。

命令动作由用户配置，直接继承 BetterCode 进程可见的环境和操作系统权限，不经过 Agent 工具权限系统。文档和启动诊断必须明确该信任边界。

### F6：提示词动作

提示词动作生成一条系统级运行时补充指令，并只注入下一次模型请求。注入内容不写入用户消息，不进入稳定 System Prompt，不永久保留在对话历史，也不改变可缓存的工具定义。

`turn_start` 和 `user_message` 产生的提示词必须能够影响当前轮次的首个模型请求；`assistant_message` 和 `post_tool_use` 产生的提示词在存在后续 Agent 迭代时影响下一次模型请求，否则保留到下一次可用模型请求。多个提示词按 Hook 的稳定执行顺序合并，并在成功注入后一次性消费。

`system_stop` 不存在后续模型请求，因此不得配置提示词动作。提示词动作必须同步完成，不支持后台异步执行。

### F7：HTTP 动作

HTTP 动作向用户配置的 HTTP 或 HTTPS 地址发送请求，支持声明方法、请求头和请求体，并能把当前事件上下文作为结构化数据发送。请求具有固定默认超时和可配置超时，响应正文必须有界读取。

在 `pre_tool_use` 中，HTTP 响应可以返回与命令动作相同的结构化 `allow` 或 `deny` 决定。只有成功响应且合法解析出的明确 `deny` 可以阻断工具；连接失败、超时、非成功状态、非法 JSON 或非法决定只记录 Hook 失败并继续主流程。

HTTP 动作由用户配置，本章不实现域名、地址、端口或响应来源限制。配置中的认证信息不得出现在普通诊断和错误日志中。

### F8：子 Agent 占位动作

规则模型必须接受子 Agent 动作所需的稳定基础字段，以便后续章节接入真实执行器。本章触发该动作时不启动模型或 Agent，不修改主会话，只记录“当前版本未实现”的 Hook 诊断并继续主流程。

子 Agent 占位动作不得用于 `pre_tool_use` 拦截，也不得产生伪造的允许或拒绝决定。

### F9：工具执行前拦截

`pre_tool_use` 在工具名称可见性、Plan Mode 和参数 Schema 校验通过后触发，并早于权限系统确认、文件快照和工具实际执行。它适用于内置工具、MCP 工具和 Skill 专属工具。

匹配的同步 Hook 按稳定配置顺序执行。任一命令或 HTTP 动作明确返回 `deny` 后，后续 `pre_tool_use` Hook 不再执行，工具调用不得进入权限确认或工具实现。拒绝结果必须使用稳定错误代码，包含面向模型的拒绝原因和非敏感来源信息，并作为普通工具结果回灌 Agent Loop，使模型可以调整策略继续运行。

所有执行前 Hook 都未明确拒绝时，工具调用继续经过现有权限系统。Hook 的 `allow` 只表示本条 Hook 不阻断，不能绕过危险命令黑名单、路径沙箱、权限规则、权限模式或人工确认。

被 Hook、Plan Mode、Schema 或权限系统拒绝的调用不触发 `post_tool_use`。实际进入工具实现并得到结果的调用，无论成功还是工具自身失败，都触发一次 `post_tool_use`；执行后 Hook 不得改写原工具结果。

### F10：执行控制

Hook 支持以下可选控制：

- **只运行一次**：同一规则在当前 BetterCode 进程中第一次成功完成后不再执行，重启后重置。本章不持久化该状态。
- **后台异步**：动作启动后不等待结果，主流程立即继续；后台失败仍记录日志，并在关闭时有界等待或取消。
- **命令超时**：命令动作超过声明时限后终止并按 Hook 失败处理。

`pre_tool_use` 禁止只运行一次和后台异步，避免安全检查在后续调用中失效或工具在决定产生前执行。提示词动作禁止后台异步。一次性后台动作在首次调度时进入“执行中”状态，防止并发重复启动；成功后保持已完成，失败后允许未来事件重试。

### F11：稳定执行顺序

Hook 配置按用户全局、项目共享、项目本地的层级顺序加载，同一文件内按声明顺序执行。首版不提供显式数值优先级、依赖关系或拓扑排序。

同步 Hook 按稳定顺序串行执行。后台 Hook 按稳定顺序启动，但不保证完成顺序。提示词动作的合并顺序、执行前首个拒绝规则和日志中的规则位置必须在相同配置下保持确定。

### F12：三层 YAML 配置

Hook 规则从以下文件加载：

- 用户全局：`~/.bettercode/hooks.yaml`。
- 项目共享：`<project>/.bettercode/hooks.yaml`。
- 项目本地：`<project>/.bettercode/hooks.local.yaml`。

项目本地文件用于当前工作副本的个人自动化，应加入 Git 忽略；项目共享文件适合团队维护；用户全局文件提供跨项目默认动作。不存在的文件等价于空规则集。

所有层必须在任何 Hook 触发前完成读取和集中校验。任一存在的配置文件语法、结构或规则无效时，BetterCode 拒绝启动，不得带着部分 Hook 集合运行。项目配置路径必须解析真实路径并限制在项目根目录内，防止通过符号链接读取外部伪造配置。

### F13：失败隔离与日志

除合法的 `pre_tool_use` 明确拒绝外，Hook 动作的非零退出、超时、网络错误、非法响应、占位动作、日志器异常和后台任务失败都不得改变 Agent 的停止原因、工具结果、历史配对或会话状态。

每次 Hook 失败必须产生有界、结构化日志，至少包含配置层、文件、规则位置、事件、动作类型和脱敏错误摘要。日志不得记录 API Key、认证请求头、完整敏感环境变量或未经限制的工具输出。单个 Hook 失败后，其他符合条件的 Hook 继续执行；执行前 Hook 仅在明确拒绝时短路。

### F14：取消与关闭

同步 Hook 必须接收当前 Agent 或应用生命周期的取消信号。用户取消期间，尚未开始的 Hook 不再启动，正在等待的命令和 HTTP 请求应尽快终止；取消 Hook 本身不能覆盖 Agent 原有的取消结果。

BetterCode 关闭时停止接受新事件，取消仍在运行的后台动作并在有限时间内等待清理，然后触发系统停止所需的同步动作。重复关闭必须幂等，不能重复执行结束事件或遗留计时器、子进程和网络请求。

## 非功能需求

- **N1：主流程可靠性**
  运行期 Hook 故障必须失败开放并隔离，只有结构化且明确的执行前拒绝能够阻断工具。

- **N2：安全组合**
  Hook 允许结果不能绕过 Plan Mode、权限系统、项目路径边界和危险命令黑名单；Hook 拒绝必须发生在工具副作用之前。

- **N3：确定性**
  相同配置和事件输入必须得到相同匹配集合、同步执行顺序、提示词合并顺序和首个拒绝结果。

- **N4：响应性**
  无匹配 Hook 时生命周期发布开销应保持轻量；后台动作不得阻塞 Agent，命令和 HTTP 响应必须有超时和大小边界。

- **N5：缓存兼容**
  Hook 不得改变稳定 System Prompt 和稳定工具定义；动态提示词只走现有运行时 instruction 消息通道。

- **N6：配置可维护性**
  三层 YAML 使用同一版本化结构，错误能够定位到文件和规则，匹配字段和事件上下文具有清晰文档。

- **N7：可测试性**
  配置加载、条件匹配、事件顺序、四类动作、拦截、取消、一次性状态和失败隔离均可通过假执行器验证，不依赖真实模型服务或外部 HTTP 服务。

- **N8：兼容性**
  Hook 系统必须兼容现有 OpenAI 兼容 Provider、Anthropic Provider、Agent Loop、Plan Mode、权限系统、MCP、上下文压缩、会话恢复、记忆和 Skill 系统。

- **N9：平台范围**
  命令动作首版支持 macOS 和 Linux 的系统 Shell，不要求兼容 Windows Shell 语义。

- **N10：信任边界透明**
  Hook 配置属于用户主动安装的本地自动化代码，命令和 HTTP 动作不受 Agent 工具权限控制。BetterCode 只保证配置来源分层、项目配置路径边界、日志脱敏和执行资源边界，不提供操作系统沙箱或网络隔离。

## 不做的事

- 不实现子 Agent 动作的真实运行、历史选择、模型选择或结果回流。
- 不持久化 `once` 已执行状态，BetterCode 重启后允许再次执行。
- 不提供 Hook 的显式数值优先级、依赖声明、并行拓扑或用户自定义排序。
- 不实现 Hook 配置热更新；修改 YAML 后需要重启 BetterCode。
- 不允许 Hook 动态注册新事件、新动作类型或可执行代码插件。
- 不允许 Hook 修改已经生成的用户消息、助手消息、工具参数或工具结果。
- 不实现 HTTP 域名白名单、代理、证书固定、网络沙箱或请求配额。
- 不提供 Hook 运行审计查询、日志轮转界面或长期统计分析。
- 不把 Hook 规则交给模型选择，Hook 是否运行只由事件和确定性条件决定。
- 不改变现有权限 YAML 的配置格式、优先级和外部匹配语义。
- 不为模型流式文本的每个增量触发消息 Hook。

## 验收标准

- **AC1：三要素校验**
  缺失事件或动作的规则导致启动失败；省略条件的有效规则在对应事件每次触发时执行。（覆盖 F1）

- **AC2：生命周期覆盖**
  启动、首会话、普通用户任务、多次模型工具迭代、清空、恢复和关闭场景产生规定的系统、会话、轮次、消息和工具事件，开始与结束事件顺序稳定且不重复。（覆盖 F2、F14）

- **AC3：轮次边界**
  一次用户输入触发一次 `turn_start` 和一次 `turn_end`，即使 Agent 内部发起多次模型请求也不重复触发轮次事件；停止原因在结束上下文中可见。（覆盖 F2、F3）

- **AC4：结构化上下文**
  工具执行前条件能分别读取工具名和嵌套参数，执行后能读取有界工具结果；Hook 不能通过事件对象修改原调用或历史。（覆盖 F3）

- **AC5：条件匹配**
  精确、glob、正则和反向匹配分别只命中预期值；`all` 与 `any` 行为正确，混用、嵌套、非法正则和未知字段声明在启动期失败。（覆盖 F4）

- **AC6：权限兼容**
  公共匹配基础能力接入后，现有权限规则的工具级、精确和 glob 行为及全部回归测试保持不变。（覆盖 F4、N8）

- **AC7：命令动作**
  命令在项目根运行并收到事件上下文；成功、非零退出、超时、取消、超大输出和非法结构化结果均得到有界且可区分的执行结果，不遗留子进程。（覆盖 F5、F13、F14）

- **AC8：一次性提示词注入**
  提示词动作只出现在下一次 Provider 请求的 runtime instruction 中，之后自动移除，不写入真实历史，也不改变稳定 System Prompt 和工具定义。（覆盖 F6、N5）

- **AC9：HTTP 动作**
  本地测试 Server 能收到声明的方法、请求头和结构化上下文；成功、拒绝、非成功状态、超时、取消和超大响应均按规范处理，认证值不进入日志。（覆盖 F7、F13、F14）

- **AC10：子 Agent 占位**
  合法子 Agent 配置可以加载，触发时不调用 Provider、不创建 Agent，只记录未实现诊断并继续主流程；将其用于执行前拦截时配置校验失败。（覆盖 F8）

- **AC11：执行前拒绝**
  匹配的命令或 HTTP Hook 返回明确 `deny` 后，权限确认、文件快照和工具实现调用次数均为零；拒绝原因以稳定 Hook 错误结果回灌，Agent 随后能改用其他工具完成任务。（覆盖 F9）

- **AC12：允许不可越权**
  Hook 返回 `allow` 后，调用仍会被 Plan Mode、危险命令黑名单、路径沙箱或显式权限拒绝拦截，Hook 不能扩大工具权限。（覆盖 F9、N2）

- **AC13：执行后事件**
  实际执行的成功和失败工具各触发一次 `post_tool_use`，执行前、Schema、Plan Mode 或权限拒绝的调用不触发；执行后 Hook 不能替换原工具结果。（覆盖 F9）

- **AC14：执行控制**
  一次性规则在进程内成功后不再运行、失败后可以重试；后台规则不阻塞主流程；`pre_tool_use` 配置 `once` 或后台异步以及提示词配置后台异步时均在启动期失败。（覆盖 F10）

- **AC15：稳定顺序**
  用户、项目、本地三层及文件内多条规则按固定顺序执行；同步结果、提示词合并和首个拒绝在重复运行中一致，后台动作只保证启动顺序。（覆盖 F11）

- **AC16：配置严格失败**
  三层任一 YAML 存在语法、版本、未知字段、非法条件或动作错误时 BetterCode 拒绝启动，并报告文件和规则位置；不存在的文件不报错，项目符号链接逃逸被拒绝。（覆盖 F12）

- **AC17：失败隔离**
  普通、执行前和后台 Hook 分别发生动作错误时，除明确拒绝外均不改变 Agent 停止原因、历史工具配对和后续 Hook 执行；日志字段完整、有界且脱敏。（覆盖 F13、N1）

- **AC18：兼容回归**
  无 Hook 配置时现有 Agent、权限、MCP、上下文、会话、记忆、命令和 Skill 测试保持通过，Provider 请求除必要的运行时注入外不发生变化。（覆盖 N8）
