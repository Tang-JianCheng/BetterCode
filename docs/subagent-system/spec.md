# BetterCode 子 Agent 系统 Spec

## 背景

BetterCode 已具备工具系统、Agent Loop、Plan Mode、权限控制、上下文管理、记忆、Skill 和生命周期 Hook，但所有模型任务仍主要运行在主 Agent 的单一上下文中。复杂任务需要研究、验证、测试或专项审查时，主 Agent 只能亲自展开全部过程，工具结果和中间推理会持续占用主对话窗口，也无法安全地把多个独立子任务交给不同角色异步完成。

本章为 BetterCode 增加统一的子 Agent 系统。主 Agent 可以通过一个稳定的 `Agent` 工具创建定义式或 Fork 式子 Agent。每个子 Agent 拥有独立运行时状态，在受限工具和非交互权限策略下自主运行到停止；基础 Provider、Hook、工具注册与项目文件系统继续共享。前台任务可以显式、超时或手动转入后台，后台结果在安全请求边界回流主对话，不主动打断正在进行的主 Agent 请求。

## 术语

- **定义式子 Agent**：从空白消息历史启动，并在整个生命周期携带预定义角色指令和角色约束的子 Agent。
- **Fork 式子 Agent**：从父 Agent 最近一次模型请求的合法历史前缀创建，继承父 Agent 当时可见工具和 Provider，用于基于相同上下文并行处理新任务。
- **前台任务**：父 Agent 等待子 Agent 完成，并把最终结果作为当前 `Agent` 工具调用结果接收的任务。
- **后台任务**：`Agent` 工具先返回任务编号，子 Agent 继续独立运行；完成结果稍后排队回流主对话。
- **来源覆盖**：同名角色只采用最高优先级来源的定义，低优先级定义不会与其合并。
- **安全请求边界**：主 Agent 即将自然发起下一次模型请求、但尚未构造最终请求内容的时刻。结果回流可以影响该请求，但不得额外唤醒或中断主 Agent。

## 目标

- 让主 Agent 通过一个稳定工具委派定义式和 Fork 式子任务。
- 用独立上下文隔离子任务的中间消息、Token、权限状态和读取缓存。
- 通过分层角色定义、模型档位和多层工具过滤约束子 Agent 能力。
- 支持前台等待、自动转后台、手动转后台和强制后台 Fork。
- 让后台任务状态、结果和用量可查询，并把完成结果可靠回流原主会话。
- 激活 Hook 系统已经预留的子 Agent 动作，同时保持 Hook 失败不影响主流程。

## 功能需求

### F1：统一 Agent 工具

BetterCode 必须只注册一个名称和参数结构稳定的 `Agent` 工具，通过类型参数区分 `defined` 和 `fork` 两条执行路径。不得为每个角色动态注册独立工具，也不得因角色热更新改变 Provider 看到的工具名称列表。

定义式调用必须指定角色名和任务描述，并可显式要求后台执行。Fork 式调用必须指定任务描述，始终后台执行，不允许请求前台等待。参数不完整、类型不兼容、角色不存在或角色不可用时，工具返回结构化错误，不得使父 Agent Loop 崩溃。

`Agent` 是编排型系统工具，自身不直接获得文件或命令权限；子 Agent 发起的每个普通工具调用仍必须经过该子 Agent 的 Hook、工具过滤、路径沙箱、危险命令黑名单和权限策略。所有子 Agent 都不得看到或调用 `Agent` 工具，防止无限嵌套。

### F2：角色定义格式

定义式角色必须使用带 YAML frontmatter 的 Markdown 文件描述。frontmatter 至少支持以下元信息：

- 唯一角色名和用途说明；
- 可选工具白名单；白名单缺省表示从当前完整工具集合开始，显式空列表表示不开放普通工具；
- 可选工具黑名单；与白名单冲突时黑名单优先；
- 必填后台工具白名单，可为空；任务进入后台后只保留该名单与前台可见工具的交集；
- 模型档位：`inherit`、`haiku`、`sonnet` 或 `opus`；
- 正整数最大 Agent 迭代数；
- 权限模式：`strict`、`default` 或 `allow`。

Markdown 正文是角色固定指令，定义身份、职责、边界和工作风格。该指令伴随定义式子 Agent 整个生命周期，但不得写入主 Agent 的长期历史。

BetterCode 必须提供一个内置 `general` 角色，供一般委派和未指定角色的 Hook 子 Agent 使用。该角色不得开放 `Agent` 工具，其后台工具白名单默认只包含内置只读文件与代码搜索能力。

### F3：角色多来源加载与覆盖

角色来源优先级必须为：项目级高于用户级，高于内置，高于插件。插件角色目录由外部贡献接口传入；本章不负责发现、安装或管理插件。

同名角色只选择最高优先级定义。同一来源出现重复角色，或被选中的最高优先级定义解析失败、字段非法、引用未知工具、引用不可用模型档位时，该角色必须被禁用并产生可见诊断；不得回退到低优先级同名角色，也不得阻止其他合法角色或 BetterCode 整体启动。

角色刷新后，新任务使用最新有效快照；已经运行的子 Agent 保持启动时的角色、工具和模型快照，不在运行中改变能力。

### F4：模型档位映射

BetterCode 配置必须支持稳定的 `agent_models` 映射，把 `haiku`、`sonnet`、`opus` 档位分别映射到现有 Provider 名称。角色使用 `inherit` 时沿用创建它的父 Agent Provider；使用具体档位时解析到对应 Provider。

角色引用未配置档位或档位指向不存在的 Provider 时，该角色按无效定义处理。Provider 客户端应按现有缓存方式复用，不为每个子 Agent 重复创建同一 Provider 实例。

### F5：定义式子 Agent 启动

定义式子 Agent 必须从空白消息历史启动，以角色正文作为固定角色指令，以调用参数中的任务描述作为首条任务消息。它不得继承父对话消息、父 Agent 的临时 Skill 激活状态、父 Agent 的会话权限规则或父 Agent 的上下文压缩摘要。

定义式子 Agent 使用角色指定的模型、最大迭代数、权限模式和工具过滤结果运行。前台完成时，最终文本和停止原因作为当前 `Agent` 工具结果返回父 Agent；没有可用最终文本或异常停止时，返回包含稳定错误代码和任务诊断的结构化失败结果。

### F6：Fork 式子 Agent 与缓存前缀

Fork 式子 Agent 必须继承父 Agent 最近一次已发送模型请求所使用的 Provider、稳定 System Prompt、工具定义和合法消息前缀，并在该前缀后追加 Fork 任务。快照边界位于产生当前 `Agent` 工具调用的模型响应之前，不得复制尚未配对的当前助手工具调用消息，也不得伪造临时工具结果。

Fork 首次请求必须尽量保持父请求的可缓存前缀字节与顺序稳定，使支持 prompt cache 的 Provider 能复用 System Prompt、工具描述和父历史。BetterCode 必须记录 Fork 首次请求的缓存创建与缓存读取用量，供任务详情和测试验证。

Fork 不携带定义式角色正文，不允许切换 Provider，始终进入后台。Fork 最大迭代数使用全局可配置值，默认与主 Agent 默认迭代上限一致。

### F7：运行时隔离与基础设施共享

每个子 Agent 必须独立维护：

- 消息历史和上下文压缩状态；
- 权限模式、会话级临时规则和权限事件追踪；
- 文件读取缓存或其他仅用于本次运行的读取状态；
- Token 累计、停止原因、取消信号和 Agent 迭代计数；
- 当前角色与工具可见性快照。

子 Agent 可以共享 Provider 客户端、Hook 引擎、工具实现注册、MCP 连接和同一个项目文件系统。共享基础设施不得导致一个子 Agent 的消息、临时授权、Token 或取消状态泄漏到父 Agent或其他子 Agent。

### F8：非交互权限策略

子 Agent 必须采用“跑到底”的非交互模式，任何前台或后台子 Agent 都不得打开权限确认界面。危险命令黑名单与项目路径沙箱始终生效，不可被角色或权限模式绕过。

角色权限模式为 `strict` 或 `default` 时，未被规则明确允许的调用必须直接拒绝，并把普通权限失败结果回灌子 Agent，使其可以调整方案继续运行；不得等待用户决定。角色权限模式为 `allow` 时，可按现有放行模式处理未命中规则，但仍受黑名单、沙箱、明确 deny 规则、Hook 拒绝和工具过滤限制。

每个子 Agent 的会话级临时规则必须独立。子 Agent 不得继承父 Agent 的临时授权，也不得把自身临时授权写回父 Agent 或其他子 Agent；用户级、项目级和本地持久规则继续作为共享配置来源读取。

### F9：多层工具过滤

定义式子 Agent 的可见工具必须按以下顺序收窄：完整注册工具集合、全局子 Agent 禁用列表、角色白名单、角色黑名单；进入后台后再与角色后台工具白名单取交集。任一较高安全层拒绝的工具都不得被后续层重新放开。

Fork 式子 Agent 继承父 Agent 创建 Fork 时的实际可见工具集合，进入后台后只移除全局子 Agent 禁用工具和 `Agent` 工具，不使用定义式角色后台白名单。

工具过滤必须同时作用于发送给 Provider 的工具定义和执行前校验。即使模型构造出不可见工具调用，也只能收到结构化不可用结果，不能绕过过滤执行。任务从前台转入后台时，后台白名单只约束尚未开始的后续工具调用，不撤销已经授权并开始执行的操作。

### F10：自主运行与停止

子 Agent 必须复用 ReAct Agent Loop 自主运行，持续进行模型请求、工具执行和结果回灌，直到模型不再请求工具或命中停止条件。停止条件至少包括：自然完成、最大迭代数、取消、连续未知工具达到上限、上下文管理失败和流式响应错误。

子 Agent 不得请求用户补充输入。模型输出问题或需要用户决策时，只能基于已有信息给出受限结果并结束。定义式角色达到自身最大迭代数时停止；Fork 达到全局 Fork 上限时停止。

### F11：三种后台进入方式

定义式子 Agent 必须支持三种进入后台的方式：

1. 调用 `Agent` 工具时显式指定后台；
2. 前台等待超过全局阈值后自动转后台；
3. 前台运行期间用户按 `Ctrl+B` 手动转后台。

前台自动转后台阈值必须可配置，默认 `120` 秒，单次工具调用不得覆盖。Fork 式子 Agent 从创建开始即强制后台，不经过前台等待。

转后台操作不得重启 Agent、丢失上下文、重复执行工具或重置用量。父 Agent 必须立即收到包含任务编号和当前状态的成功工具结果，并继续自身循环。任一时刻最多只有一个可由 `Ctrl+B` 切换的前台子 Agent；没有可切换任务时快捷键不得改变其他运行状态。

### F12：后台任务管理

进程内后台任务管理器必须为每个任务分配唯一编号，并记录至少以下信息：类型、角色或 Fork 来源、父会话、创建时间、开始时间、结束时间、当前状态、后台进入原因、停止原因、最终结果或错误、迭代数、Token 用量和缓存用量。

任务状态至少包括等待、运行、已完成、失败和已取消。状态变化必须单向且可观测，重复完成或迟到事件不得覆盖终态。多个后台任务可以并行运行；单个任务失败不得取消其他任务或主 Agent。

后台任务不跨 BetterCode 进程持久化。关闭应用、清空当前会话或恢复其他会话时，属于被替换会话的未完成任务必须取消，迟到结果不得写入新会话。

### F13：后台结果排队回流

后台任务完成后，BetterCode 必须立即在界面显示包含任务编号和结果状态的通知，并把有界、结构化的完成消息排入创建任务的主会话。回流消息至少包含任务编号、类型、停止原因、结果摘要和 Token 用量；完整结果继续保存在进程内任务记录中供查询。

结果不得伪装成用户输入，不得污染稳定 System Prompt 或工具缓存通道。主 Agent 在下一个自然安全请求边界读取已排队结果：如果当前 Agent Loop 后续本来就会继续请求模型，则可在该请求中注入；如果当前没有后续请求，则等待下一次用户触发的模型请求。后台完成本身不得唤醒模型、打断流式响应或强制增加一次请求。

多个结果按完成顺序回流，每个结果最多消费一次。结果被主 Agent 请求消费后必须进入可恢复的主会话历史；会话已被清空、恢复或关闭时不得跨会话回流。

### F14：任务查询与界面控制

BetterCode 必须新增 `/tasks` 本地命令。无参数时按可预测顺序列出当前会话的后台任务摘要；传入任务编号时显示该任务的状态、后台进入原因、停止原因、结果摘要、迭代数、Token 用量和缓存用量。未知任务编号返回明确提示并引导查看 `/tasks`。

前台子 Agent 运行时，TUI 必须能够接收 `Ctrl+B` 并把切换请求交给当前任务；不要求在 Agent 运行期间开放普通文本输入或其他斜杠命令。任务通知、查询和快捷键不得绑定到 Agent Loop 内部实现，非 TUI 调用方应能通过稳定事件或控制接口观察相同行为。

### F15：Hook 子 Agent 动作

Hook 系统现有的 `agent` 动作必须从占位行为升级为真实定义式子 Agent 执行。现有只包含 `type: agent` 和 `prompt` 的配置继续有效，默认使用内置 `general` 角色；动作可新增可选角色字段指定其他定义式角色。Hook 的同步或后台执行设置继续生效，Hook agent 动作不得创建 Fork。

Hook 子 Agent 使用与普通定义式子 Agent 相同的角色、模型、权限、工具过滤、后台管理和取消语义。`pre_tool_use` 继续禁止 agent 动作。Hook 子 Agent 的配置错误在 Hook 集中校验阶段暴露；运行失败只写 Hook 日志并按既有失败开放策略继续，不得改变主 Agent、会话或应用生命周期结果。

### F16：事件、通知与结果边界

子 Agent 生命周期必须产生与界面解耦的异步事件，至少覆盖创建、开始、进度、前台转后台、工具调用、工具结果、Token 用量、完成、失败和取消。父 Agent 的普通流式文本不得与子 Agent 中间文本混为同一消息；默认只向主对话回流子 Agent 最终结果。

任务结果、错误和通知必须设置大小上限并避免泄露 Provider 密钥、Hook 密钥或原始权限配置。内部异常必须归一化为稳定任务状态或工具结果，不能产生未处理 Promise 拒绝或使 BetterCode 进程退出。

## 非功能需求

- **N1：兼容性**  无子 Agent 调用时，现有主 Agent、Plan Mode、工具、权限、MCP、上下文、会话、记忆、Skill、Hook 和 Provider 行为保持不变。
- **N2：工具缓存稳定性**  角色增删和热更新不得改变统一 `Agent` 工具的名称与 Schema；Fork 首次请求应尽量复用父请求的稳定缓存前缀。
- **N3：隔离性**  并发子 Agent 之间不得共享可变消息、临时权限、上下文计数或取消控制器。
- **N4：安全性**  子 Agent 永远不能调用 `Agent` 工具；工具执行同时受可见性校验、Hook、黑名单、沙箱和权限策略约束。
- **N5：可取消性**  应用关闭、会话替换和父任务明确取消时，相关前台等待与后台任务应尽快停止；取消不得回流成成功结果。
- **N6：可观测性**  每个任务都有稳定编号、终态、停止原因和独立 Token 用量；缓存读取字段可用于验证 Fork 缓存策略。
- **N7：资源边界**  后台通知、结果摘要、错误文本和任务事件必须有大小限制；已结束任务的进程内保留数量必须可配置或有固定上限，避免长时间运行无限增长。
- **N8：并发一致性**  任务状态更新和结果消费必须避免重复、乱序覆盖与跨会话写入。由于本章不提供 Worktree，多个 Agent 对同一项目文件的业务级写入冲突不做自动合并。
- **N9：配置诊断**  角色错误按单角色隔离并提供来源、文件和原因；全局子 Agent 配置结构错误必须在启动期给出明确错误。
- **N10：命名一致性**  用户可见文档、提示、错误和内置角色必须使用 BetterCode 名称，不得出现旧系统名。

## 不做的事

- 不实现 Worktree、容器或进程级文件系统隔离。
- 不实现多个 Agent 的团队拓扑、角色协商、投票、共享黑板或自动任务拆分。
- 不持久化后台任务本身，也不在 BetterCode 重启后恢复运行。
- 不实现插件发现、插件安装、角色市场、角色版本管理或远程分发。
- 不允许子 Agent 继续创建子 Agent，不支持递归委派。
- 不让后台完成事件主动唤醒主模型，也不在主 Agent 请求中途插入结果。
- 不提供子 Agent 的交互式权限确认或追问用户能力。
- 不自动解决父 Agent 与后台子 Agent 对同一文件的并发编辑冲突。
- 不新增网络访问限制、资源配额或跨任务审计日志系统。

## 验收标准

- **AC1：统一工具稳定性**  启动后 Provider 始终只看到一个 `Agent` 工具；增加、覆盖、禁用或热更新角色后工具名称和 Schema 不变。合法定义式与 Fork 式参数分别进入正确路径，非法组合返回结构化错误。（覆盖 F1）
- **AC2：角色解析**  合法 frontmatter 与正文可加载为角色；工具白名单、黑名单、后台白名单、模型档位、最大迭代数和权限模式均按定义生效，内置 `general` 可被调用。（覆盖 F2）
- **AC3：来源覆盖与故障隔离**  同名角色按项目、用户、内置、插件顺序覆盖；最高层定义损坏时该角色被禁用且不回退，其他角色和 BetterCode 正常启动，诊断能指出来源文件和原因。（覆盖 F3）
- **AC4：模型解析**  `inherit` 使用父 Provider，三个档位分别解析到 `agent_models` 指定 Provider；缺失或无效映射只禁用引用它的角色，同一 Provider 客户端被复用。（覆盖 F4）
- **AC5：定义式隔离**  定义式子 Agent 从空历史和固定角色指令启动，看不到父消息、父 Skill 激活或父临时权限；前台自然完成时父 Agent 收到最终文本，异常停止时收到稳定失败结果。（覆盖 F5、F7）
- **AC6：Fork 缓存与历史合法性**  Fork 请求继承父请求之前的合法消息前缀和实际可见工具，不包含当前未配对工具调用；支持缓存的模拟 Provider 显示首次请求命中预期缓存前缀，并记录缓存读取用量。（覆盖 F6）
- **AC7：状态隔离**  两个并发子 Agent 的消息、上下文压缩、读取缓存、临时权限、Token、迭代数和取消信号互不影响；共享 Provider、MCP、Hook 和文件系统仍可正常使用。（覆盖 F7）
- **AC8：非交互权限**  `strict` 与 `default` 下未命中规则的调用立即拒绝且不弹窗，子 Agent 能收到失败后继续调整；`allow` 仍无法绕过危险命令黑名单、路径沙箱、明确 deny、Hook deny 和工具过滤；临时规则不跨 Agent。（覆盖 F8）
- **AC9：工具多层过滤**  全局禁止、角色黑名单、角色白名单和后台白名单按优先级收窄，Provider 定义与执行校验一致；Fork 继承父可见工具但始终移除 `Agent`，模型伪造不可见工具调用也不能执行。（覆盖 F9）
- **AC10：自主停止**  定义式与 Fork 式子 Agent 能连续使用工具直到自然完成，并分别在取消、未知工具上限、上下文错误、流错误和迭代上限下得到正确终态，不请求用户交互。（覆盖 F10）
- **AC11：后台三路径**  显式后台立即返回任务编号；前台超过默认 120 秒自动转后台；按 `Ctrl+B` 手动转后台；三种方式均保持同一任务编号、历史、已执行工具和累计用量，Fork 从创建起即为后台。（覆盖 F11）
- **AC12：任务状态与隔离失败**  多个后台任务可并发更新状态、结果和用量，单个失败不影响其他任务或主 Agent；重复或迟到完成事件不能覆盖终态。清空、恢复会话或关闭应用会取消未完成任务，结果不写入新会话。（覆盖 F12）
- **AC13：异步回流**  后台完成时界面立即显示通知，但不会额外调用 Provider；结果在主 Agent 下一次自然请求边界按完成顺序各注入一次并进入主历史，完整结果可通过任务编号查询。（覆盖 F13）
- **AC14：任务查询与手动控制**  `/tasks` 能列出当前会话任务，`/tasks <id>` 能显示状态、原因、结果摘要、迭代和缓存用量；未知编号有明确提示。前台运行时 `Ctrl+B` 有效，无任务时无副作用。（覆盖 F14）
- **AC15：Hook Agent 落地**  旧格式 Hook agent 动作使用 `general` 角色真实运行，可选角色字段生效，同步与后台行为正确；`pre_tool_use` 配置仍被拒绝，子 Agent 失败只写 Hook 日志而不改变主流程结果。（覆盖 F15）
- **AC16：事件与安全边界**  创建到终止的关键状态均通过异步事件可观察，子 Agent 中间文本不混入主消息；超长结果和错误被有界处理，敏感配置不出现在通知或任务详情，运行异常不导致未处理拒绝。（覆盖 F16、N5、N7）
- **AC17：兼容回归**  未使用子 Agent 时，现有完整类型检查和测试继续通过；OpenAI 兼容与 Anthropic Provider、Plan Mode、权限、MCP、上下文、会话、记忆、Skill 和 Hook 的既有行为无回归。（覆盖 N1、N2、N4、N8、N9）
- **AC18：范围确认**  重启 BetterCode 后旧后台任务不会恢复；系统不创建 Worktree、不允许递归子 Agent、不主动解决并发文件冲突，也不实现插件发现或团队编排。（覆盖“不做的事”）
