# BetterCode 五层权限系统 Spec

## 背景

BetterCode 已具备六个核心工具和可自主连续执行工具的 Agent Loop。当前工具调用只受参数校验、路径边界、Plan Mode 和超时控制约束；进入执行模式后，模型发起的有效调用会直接运行，用户无法按工具、命令或路径设置权限，也无法在高风险操作前介入。

本章为 BetterCode 增加五层权限防御：不可配置的危险命令黑名单、项目路径沙箱、可配置权限规则、多档权限模式以及人在回路确认。权限拒绝作为可恢复的工具结果返回 Agent Loop，使模型可以改用更安全的方案继续任务。

## 目标

- 在工具执行前统一完成权限判断，未经允许的副作用不得发生。
- 永久拦截已知高危命令，任何配置、模式或人工授权都不能绕过。
- 将专用文件工具的访问范围限制在项目根目录内，并防止通过符号链接逃逸。
- 支持按工具及参数或路径模式配置允许、拒绝规则。
- 提供严格、默认、放行三档权限模式，满足不同信任程度下的工作方式。
- 对规则未明确决定的操作提供人在回路确认，并支持本次、当前会话和永久三种授权时效。
- 按确定的层级合并会话、项目本地、项目共享和用户全局规则。
- 保持 Agent 与交互界面解耦，使不同界面可以独立实现权限确认体验。

## 权限判定顺序

每次工具调用按以下顺序判定，前一层给出最终拒绝时不得被后续层覆盖：

1. **危险操作黑名单**：命中已知高危命令时永久拒绝。
2. **路径沙箱**：专用文件工具的目标真实路径不在项目根目录内时永久拒绝。
3. **会话临时规则**：当前会话中产生的临时允许或拒绝规则。
4. **项目本地规则**：仅对当前本地项目生效、默认不参与版本共享的规则。
5. **项目共享规则**：项目内可随版本控制共享的规则。
6. **用户全局规则**：当前用户对所有项目的默认规则。
7. **权限模式默认行为**：仅在上述规则均未明确命中时生效。
8. **人工确认**：默认模式下，将仍未决定的调用交给用户。

同一层中如果多条规则命中，以更具体的模式优先；具体程度相同则以配置中靠后的规则优先。显式 `deny` 与 `allow` 不因权限模式改变，权限模式只决定未命中规则的调用。

## 功能需求

### F1：统一权限入口

所有已注册工具都必须在实际执行前经过同一套权限判定。权限检查应取得工具名称、调用参数、工具副作用类别、项目根目录和当前会话权限状态，并给出允许、拒绝或需要确认三种结果。未经允许时不得调用工具执行方法。

### F2：不可配置的危险命令黑名单

命令执行工具在启动子进程前必须使用内置正则规则检查完整命令。黑名单至少覆盖直接破坏系统根目录或磁盘、格式化文件系统、写入裸设备、关闭或重启系统、典型 fork bomb 等已知高危形式。

黑名单规则属于程序内置安全边界，不从权限配置读取。即使用户规则显式允许、当前处于放行模式，或用户尝试人工确认，命中黑名单的命令仍必须拒绝，并说明命中的安全类别。

### F3：项目路径沙箱

读取、写入、编辑、按模式找文件和搜索代码内容等专用文件工具只能访问当前项目根目录。判定必须基于规范化后的真实路径；对已存在目标解析目标本身，对新建目标解析最近存在的父目录，并拒绝绝对路径、路径穿越、指向项目外的符号链接及悬空符号链接逃逸。

权限规则、权限模式和人工确认均不能允许专用文件工具越过项目根目录。BetterCode 为加载用户级权限配置而进行的内部读取属于控制面行为，不作为模型可调用的文件能力。

### F4：规则表达式

每条权限规则由结果和表达式组成，结果只能是 `allow` 或 `deny`。表达式采用“工具名(模式)”格式，例如 `run_command(git *)` 表示匹配命令参数以 `git ` 开头的命令执行调用。

规则支持以下匹配方式：

- 仅写工具名时，匹配该工具的全部调用。
- 括号内为普通文本时，支持对工具主参数或目标路径进行精确匹配。
- 括号内包含 glob 通配符时，按 glob 语义匹配工具主参数或项目相对路径。
- 工具名必须对应已注册工具；无效表达式不得静默生效。

规则匹配应使用可预测的规范化参数。路径使用相对项目根目录的标准形式，命令使用模型提交的完整命令文本，其他工具使用其声明的主匹配参数。

### F5：多层 YAML 规则配置

权限规则分别存放在三个 YAML 层级：用户全局、项目共享和项目本地。系统启动时加载并校验三层配置，再叠加当前会话的内存规则。

规则优先级从高到低为：会话临时、项目本地、项目共享、用户全局。高优先级层一旦产生明确结果，不再查询低优先级层。单个配置文件损坏时应报告文件位置和校验原因，不得把无效规则当作允许。

项目本地规则用于保存只适合当前工作副本的授权；项目共享规则用于团队共同维护；用户全局规则提供跨项目默认值。

### F6：三档权限模式

BetterCode 提供以下会话级权限模式：

- **严格模式**：规则未命中时直接拒绝，不发起人工确认。
- **默认模式**：规则未命中时请求用户确认。
- **放行模式**：规则未命中时自动允许。

三档模式都不能绕过危险命令黑名单、项目路径沙箱和显式 `deny` 规则；显式 `allow` 规则在三档模式下均有效。切换模式只影响后续尚未判定的工具调用，不追溯已经执行或拒绝的调用。

### F7：人在回路确认

默认模式遇到规则未命中的调用时，Agent 必须发出异步权限请求，至少向界面提供工具名称、关键参数、风险说明和当前项目。Agent 等待对应决定期间不得执行该工具，但界面仍可响应取消操作。

用户可以选择：

- **拒绝**：拒绝当前调用。
- **仅本次允许**：只允许当前调用，不创建规则。
- **本会话允许**：允许当前调用，并创建高优先级会话临时规则。
- **永久允许**：允许当前调用，并把对应规则写入项目本地 YAML。

人工确认只能处理可授权调用。命中黑名单或路径沙箱的调用不发起确认。永久规则写入失败时不得把授权伪装成已持久化；系统应告知失败，并保持当前调用未执行，交由用户重新决定。

### F8：批量工具调用权限

模型一次返回多个工具调用时，每个调用必须独立完成权限判定。无需确认且可并发的只读调用可以继续按既有调度策略并发执行；副作用调用以及需要人工确认的调用保持确定的串行顺序。

某个调用被拒绝不得隐式批准、取消或跳过其他尚可安全判断的调用。批次返回结果仍应与模型原始调用顺序一一对应。

### F9：结构化权限结果

权限拒绝、黑名单拦截、沙箱拦截、确认取消和权限配置错误都必须转换为结构化工具结果。结果至少包含稳定错误代码、面向模型的原因说明以及可用于调整策略的非敏感元信息。

权限错误不得包含用户全局配置的敏感内容，也不得暴露项目根目录之外文件的内容或存在性细节。

### F10：拒绝后继续 Agent Loop

单个工具调用因权限被拒绝时，不终止 Agent Loop。拒绝结果按普通工具结果回灌对话历史，模型可以解释限制、改用已允许的工具或提出更安全的操作。

只有用户取消整个运行、模型流错误、达到迭代上限或既有 Agent 停止条件触发时，当前运行才终止。拒绝后的模型重试仍需重新经过完整权限判定。

### F11：权限事件与界面解耦

Agent 通过异步事件表达权限请求和权限决定，不直接依赖终端组件。权限请求与工具调用具有稳定关联标识，迟到、重复或不匹配的决定不得导致工具误执行。

终端界面必须能够展示待确认操作并提交决定；非交互调用方也可以提供自己的权限决策器。在需要确认但没有可用决策器时，系统按拒绝处理，不能自动放行或无限等待。

### F12：取消与并发一致性

用户在等待权限确认期间取消运行时，所有待确认调用都应结束为取消结果，且不得随后执行。并发只读调用若已开始，继续遵循既有取消机制；尚未开始的副作用调用不得启动。

权限决定只对其绑定的当前调用或明确生成的规则生效，不得因并发、重试或调用标识复用而扩散到其他调用。

## 非功能需求

- **N1：安全优先**  
  黑名单和路径沙箱采用失败关闭策略；无法可靠判断时拒绝，不得因配置缺失、解析异常或界面故障自动放行。

- **N2：确定性**  
  相同项目状态、权限配置、模式和调用参数必须得到相同的规则匹配结果。规则优先级和同层冲突处理不得依赖文件系统遍历顺序。

- **N3：兼容性**  
  权限系统必须兼容现有六个工具、Agent Loop、Plan Mode、OpenAI 兼容协议和 Anthropic 协议。Provider 不感知权限配置与用户确认逻辑。

- **N4：响应性**  
  不需要人工确认的权限判断不应造成可感知延迟。等待确认不得阻塞界面事件处理，也不得阻塞与该确认无依赖关系的安全只读工作。

- **N5：可恢复性**  
  权限拒绝、配置错误、规则持久化失败和确认取消不得导致 BetterCode 主进程崩溃或破坏对话历史中的工具调用配对。

- **N6：可测试性**  
  黑名单、路径沙箱、规则解析、层级优先级、模式行为、人工确认、批量调度和拒绝后继续循环都应能在不调用真实模型 API 的情况下独立验证。

- **N7：配置可维护性**  
  三层 YAML 使用一致结构，错误信息能定位到文件和规则。项目本地配置应可与项目共享配置明确区分，避免误提交个人授权。

- **N8：平台范围**  
  本章支持 macOS 和 Linux。命令黑名单需要覆盖两者常见 Shell 形式，不要求兼容 Windows 命令语义。

- **N9：安全边界透明**  
  路径沙箱对 BetterCode 专用文件工具提供强制边界，但本章不提供容器、`chroot` 或系统调用级隔离。命令执行工具一旦获准，仍具有 BetterCode 进程的操作系统权限；其风险由黑名单、显式规则、权限模式和人工确认共同降低。

## 不做的事

- 不限制或代理网络请求，不实现域名、地址或端口级网络权限。
- 不实现 CPU、内存、进程数、磁盘空间或工具调用频率等资源配额。
- 不实现权限操作审计日志、审计查询或审计记录持久化。
- 不提供容器、虚拟机、`chroot`、系统调用过滤或操作系统级命令沙箱。
- 不承诺通过正则黑名单识别所有语义等价、编码混淆或间接执行的危险 Shell 命令。
- 不实现基于 Git 身份、操作系统账户、团队角色或远程策略服务的权限管理。
- 不实现规则同步、云端策略下发或多人审批。
- 不允许配置覆盖内置危险命令黑名单或项目路径沙箱。
- 不改变 Plan Mode 只开放读类工具的既有边界；Plan Mode 禁止的工具不会进入人工确认。
- 不为已有历史工具调用追溯执行权限判断。

## 验收标准

- **AC1：统一执行前检查**  
  对六个核心工具分别发起调用时，都能观察到工具执行前的权限判定；被拒绝的调用不会进入工具执行方法。（覆盖 F1）

- **AC2：黑名单不可绕过**  
  对删除系统根目录、格式化文件系统、写入裸设备、关闭或重启系统及典型 fork bomb 的代表性命令进行测试时，严格、默认、放行三种模式以及任意 `allow` 规则下均在启动子进程前被拒绝，并返回命中的安全类别。（覆盖 F2）

- **AC3：普通命令不被黑名单误伤**  
  常见的项目内构建、测试、Git 查询和文件查看命令不因仅包含相似文本而误命中代表性黑名单规则，之后继续按普通权限规则判断。（覆盖 F2）

- **AC4：真实路径沙箱**  
  专用文件工具访问项目内路径时可继续权限判断；使用绝对路径、`..`、指向项目外的符号链接或位于外部符号链接目录下的新文件路径时均被拒绝，且任何模式和人工授权都不能覆盖。（覆盖 F3）

- **AC5：规则表达式匹配**  
  工具级规则、精确参数规则和 glob 参数或路径规则分别只匹配预期调用；无效工具名、缺失结果、非法结果或格式错误的规则产生明确配置错误，不会静默放行。（覆盖 F4）

- **AC6：同层冲突确定性**  
  同一层存在多条匹配规则时，更具体规则优先；具体程度相同时，靠后的规则优先。重复加载相同配置得到一致结果。（覆盖 F4、N2）

- **AC7：跨层优先级**  
  构造互相冲突的用户全局、项目共享、项目本地和会话临时规则时，结果严格遵循“会话临时 > 项目本地 > 项目共享 > 用户全局”，且高层明确结果不会被低层覆盖。（覆盖 F5）

- **AC8：配置加载失败关闭**  
  任一 YAML 文件语法错误、结构错误或包含无效规则时，错误信息能指出文件与原因，相关无效配置不会产生允许结果。（覆盖 F5、N1、N7）

- **AC9：三档模式**  
  对没有命中任何规则的同一调用，严格模式直接拒绝，默认模式发起确认，放行模式自动允许；三种模式均服从黑名单、路径沙箱和显式 `deny`。（覆盖 F6）

- **AC10：仅本次允许**  
  默认模式下选择“仅本次允许”后，当前调用执行；再次提交相同调用时仍需确认。（覆盖 F7）

- **AC11：本会话允许**  
  选择“本会话允许”后，当前调用执行，同一会话内再次匹配时不再确认；新会话中该授权不存在。（覆盖 F7）

- **AC12：永久允许**  
  选择“永久允许”后，对应规则写入项目本地 YAML，当前调用执行；重新启动 BetterCode 后仍可命中该规则。模拟写入失败时当前调用不执行，并明确提示授权未持久化。（覆盖 F7）

- **AC13：拒绝和取消确认**  
  用户拒绝当前调用时工具不执行；等待确认期间取消整个运行时，待确认调用不会在决定迟到后执行。（覆盖 F7、F12）

- **AC14：批量调用调度**  
  一次响应包含多个工具调用时，每个调用独立判权，安全只读调用保持既有并发能力，副作用和确认请求按确定顺序串行处理，最终结果顺序与原调用顺序一致。（覆盖 F8）

- **AC15：结构化权限错误**  
  黑名单、路径越界、规则拒绝、缺少决策器、确认取消和配置异常分别返回可区分的稳定错误代码与可操作说明，且不泄露项目外文件内容或用户配置敏感值。（覆盖 F9）

- **AC16：拒绝后继续循环**  
  模型调用被权限拒绝后，拒绝结果进入对应工具历史，Agent Loop 继续请求模型；模型随后可以改用允许的工具并正常完成任务。（覆盖 F10）

- **AC17：事件解耦**  
  使用不依赖 Ink 的测试决策器可以接收权限请求并提交关联决定；重复、迟到或调用标识不匹配的决定均不会触发工具执行。（覆盖 F11、F12）

- **AC18：无决策器失败关闭**  
  默认模式需要确认但调用方没有提供权限决策器时，调用得到拒绝结果并继续 Agent Loop，不会自动允许或永久等待。（覆盖 F11、N1）

- **AC19：Plan Mode 回归**  
  Plan Mode 继续只暴露和执行读类工具；写入、编辑和命令工具不会因权限规则或人工确认而在 Plan Mode 中启用。（覆盖 N3）

- **AC20：既有功能回归**  
  不需要确认的工具调用、流式文本、Thinking、Token 用量、取消、迭代上限、未知工具限制以及 OpenAI 兼容和 Anthropic 协议行为保持正常。（覆盖 N3、N5）

- **AC21：自动化验证**  
  在不访问真实模型 API、不执行真实高危命令、不启动交互式终端的情况下，可以自动验证黑名单、路径沙箱、规则优先级、三档模式、确认时效、批量调度及拒绝后继续循环。（覆盖 N6）
