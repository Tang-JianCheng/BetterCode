# BetterCode 结构化系统提示与缓存策略 Spec

## 背景

BetterCode 已具备核心工具系统和 Agent Loop，能够根据模型返回的工具调用自主执行任务。目前全局指令仍然缺少清晰的职责划分，稳定指令、环境信息和会话级动态要求也没有形成明确的传递边界。这会降低模型遵守工具约定和代码规范的稳定性，同时使请求前缀频繁变化，无法充分利用不同模型服务提供的提示缓存能力。

本阶段将建立统一的结构化提示体系：长期稳定的全局规则与工具描述保持稳定，环境信息、当前模式和其他运行期补充指令通过消息通道按需注入。BetterCode 在不改变 Agent Loop 核心行为的前提下，提升指令遵守率、跨供应商一致性和缓存可观测性。

## 目标

- 将全局指令拆分为职责清晰、顺序固定、便于扩展的结构化模块。
- 将稳定内容与动态内容分离，使 Anthropic、OpenAI 和 DeepSeek 均能利用各自支持的缓存机制。
- 通过全局指令与工具描述的双重约束，提高关键工具规则的遵守率。
- 通过带特殊标签的补充消息注入环境和会话级指令，避免其被当作普通用户问题展示或回复。
- 控制任务模式指令的重复频率，在指令可靠性与输入成本之间取得平衡。
- 采集并展示缓存创建与命中用量，为缓存策略是否生效提供可观察证据。
- 准备典型人工场景，对结构化提示启用前后的行为进行定性比较。

## 功能需求

### F1：固定系统提示模块

BetterCode 必须将稳定的全局指令拆分为以下七个固定模块，并严格按顺序拼装：

1. 身份
2. 系统约束
3. 任务模式
4. 动作执行
5. 工具使用
6. 语气风格
7. 文本输出

模块之间必须使用空行分隔。每个模块只承载对应职责，整体优先级从前向后递减。系统应允许以后在不改动既有模块内容和顺序语义的情况下插入新模块。

### F2：动态内容与可选模块

环境信息不得写入稳定的固定系统提示，而应在运行期通过消息通道注入。环境信息至少包括：

- 项目根目录
- 当前工作目录
- 操作系统与平台
- 当前 Shell
- 当前日期与时区
- 当前任务模式

环境信息之后可按顺序附加以下可选模块：

1. 自定义指令
2. 已激活的 Skill
3. 长期记忆

缺少某项可选内容时必须整体省略对应模块，不得输出空模块或占位符。本阶段只消费调用方已经提供的可选内容，不负责发现、加载或维护这些内容。

### F3：稳定内容与缓存边界

固定系统提示和稳定的工具定义必须在请求之间保持内容与顺序稳定。不同协议按以下策略利用缓存：

- Anthropic 对固定系统提示和工具定义使用显式缓存标记。
- OpenAI 和 DeepSeek 保持稳定请求前缀，使用服务端自动缓存机制。
- 对话历史、环境信息和运行期补充指令通过消息通道传递，不得改写固定系统提示或工具定义。

不同协议可以使用不同的底层缓存机制，但必须向 BetterCode 上层提供统一的缓存用量语义。

### F4：运行期补充指令消息

BetterCode 必须使用 `<system-reminder>...</system-reminder>` 包裹环境信息和运行期补充指令，并通过消息通道随当前请求发送。

补充指令在 BetterCode 内部必须与真实用户消息区分，不得作为用户输入显示，不得单独触发用户消息相关行为，也不得写入持久对话历史。发送到不支持消息级系统角色的协议时，可以映射为协议支持的消息角色，但固定系统提示必须明确要求模型将该标签内容视为运行期元指令，只执行其要求，不直接对标签本身作答。

每轮补充消息只对当前请求有效，不能通过修改历史消息来追溯注入。

### F5：任务模式按轮次注入

会话级任务模式必须按 Agent 轮次注入：

- 当前模式的首轮注入完整模式说明。
- 此后每间隔 5 个 Agent 轮次再次注入完整模式说明。
- 其他轮次注入精简模式提醒。

固定系统提示中的“任务模式”模块只定义通用模式规则；当前启用的具体模式及其限制由补充指令消息声明。规划模式必须明确限制为只读分析和计划输出，执行模式必须恢复当前会话允许使用的完整工具集合。

轮次计数必须以一次模型请求为一个 Agent 轮次，在新会话或任务模式发生切换时重新开始完整注入周期。

### F6：关键工具规则双重强化

以下关键规则必须同时出现在固定系统提示的“工具使用”模块和相关工具描述中：

- 存在专用工具时优先使用专用工具，不使用通用命令绕过其约束。
- 编辑文件前必须先读取目标文件的当前内容。
- 文件和命令操作必须遵守项目根目录及当前工作目录约束。
- 工具失败后应根据结构化错误调整参数或方案，不得假定操作已经成功。

同一规则在两处的语义必须一致。工具定义的顺序和描述不得因对话轮次变化。

### F7：缓存用量采集

Provider 必须解析供应商响应中可获得的缓存相关用量，包括：

- 缓存创建输入量
- 缓存命中或缓存读取输入量

缓存用量必须与现有输入、输出和总 Token 用量一起通过统一事件流上报。供应商未返回某项数据时，应明确表示不可用或按零处理，不得将普通输入 Token 误报为缓存命中 Token。

缓存字段缺失不得中断流式响应，也不得影响文本、工具调用和原有 Token 用量事件。

### F8：缓存验证与人工对比

本阶段必须提供可重复的缓存验证步骤，至少覆盖同一会话中稳定前缀不变的连续请求，并能从 Provider 返回的缓存用量中判断是否发生缓存创建或命中。

同时必须准备一组典型人工对比场景，至少覆盖：

- 有专用工具时是否避免使用通用命令替代。
- 未读取文件时是否避免直接编辑。
- 规划模式下是否只使用只读工具并输出计划。
- 动态环境变化时是否正确使用最新环境，同时保持固定系统提示不变。
- 补充指令是否被执行但不被当作用户问题直接回复。

人工对比结果应记录实际表现和结论；本阶段不要求构建自动评分系统。

## 非功能需求

### N1：兼容性

结构化提示和缓存统计必须兼容现有 Anthropic 与 OpenAI 协议实现，DeepSeek 继续通过 OpenAI 兼容协议工作。供应商不支持显式缓存或不返回缓存统计时，原有对话与工具调用能力必须保持可用。

### N2：缓存稳定性

在固定模块、工具集合及其定义未发生配置变化时，连续请求中的固定系统提示文本、模块顺序和工具定义序列必须保持字节级稳定。环境、日期、工作目录、模式状态和对话历史的变化不得改变这些稳定内容。

### N3：行为兼容性

现有流式文本、思考内容、工具调用、工具结果、取消、错误处理和 Agent Loop 停止条件不得因本阶段改造发生回归。

### N4：可测试性

固定模块顺序、空行分隔、动态消息构造、模式注入周期、协议映射、缓存请求标记及缓存用量解析必须能够在不调用真实模型服务的情况下验证。

### N5：安全边界

动态补充指令不得扩大当前会话已有的工具权限或文件访问边界。外部提供的自定义指令、Skill 和长期记忆内容不得覆盖更高优先级的固定系统约束。

### N6：命名一致性

所有新增用户可见文档、提示内容和测试场景必须统一使用产品名称“BetterCode”。

## 不做的事

- 不加载或解析项目级指令文件。
- 不实现自动记忆提取、存储、检索或更新。
- 不实现 Skill 的发现、激活或加载机制，只接收外部已提供的 Skill 内容。
- 不接入真实 MCP 服务。
- 不构建自动化行为评分、基准测试平台或模型质量门禁。
- 不新增权限系统或交互式操作确认。
- 不改变现有 Agent Loop 的自主循环范围和停止条件。
- 不保证所有供应商都会产生缓存命中；只保证请求满足缓存条件并正确采集供应商返回的数据。

## 验收标准

- AC1（对应 F1）：生成的固定系统提示包含且仅按规定顺序排列七个固定模块，模块之间以单个空行分隔；相同输入生成完全相同的文本。
- AC2（对应 F2）：环境信息通过消息通道出现且包含六项必需字段；可选模块按规定顺序出现，缺失项不产生空标题或占位内容。
- AC3（对应 F3）：连续请求中固定系统提示和工具定义保持不变；Anthropic 请求包含显式缓存配置，OpenAI/DeepSeek 请求保持可供自动缓存复用的稳定前缀。
- AC4（对应 F4）：补充指令使用规定标签，在线路消息中存在，但不会出现在用户消息列表或持久历史中；固定系统提示明确规定其执行语义。
- AC5（对应 F5）：新会话首轮、模式切换首轮以及其后每第 5 个间隔轮次使用完整模式说明，其余轮次使用精简提醒；轮次序列可通过测试稳定复现。
- AC6（对应 F6）：固定系统提示与相关工具描述均包含专用工具优先、编辑前先读、目录约束和失败后调整四类规则，且工具描述在不同轮次保持不变。
- AC7（对应 F7）：Anthropic、OpenAI 兼容协议返回缓存字段时，统一用量事件能正确报告缓存创建与命中数据；字段缺失时流式响应正常完成且不产生错误统计。
- AC8（对应 F8）：完成至少一次可重复的缓存验证并记录缓存统计；五类人工场景均有启用结构化提示前后的实际表现、差异和结论记录。
- AC9（对应 N1、N3）：现有 Provider 与 Agent Loop 测试继续通过，文本流、工具调用、工具结果、取消和错误路径无行为回归。
- AC10（对应 N2）：仅改变环境信息、日期、工作目录、任务模式或对话历史时，固定系统提示和工具定义的序列化结果保持不变。
- AC11（对应 N4）：不访问真实 API 即可自动验证提示拼装、消息注入、模式周期、Provider 请求体和缓存用量解析。
- AC12（对应 N5）：动态补充内容尝试扩大权限或覆盖固定约束时，最终提示优先级仍明确保留固定系统约束和既有工具边界。
- AC13（对应 N6）：新增内容中的产品名称统一使用“BetterCode”。
