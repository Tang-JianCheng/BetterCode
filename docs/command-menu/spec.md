# BetterCode 动态命令面板 Spec

## 背景

Claude Code 在用户输入 `/` 的瞬间就会在提示符下方渲染动态命令面板，候选随输入实时过滤，Tab 可补全，方向键聚焦某项时展开完整说明。BetterCode 目前只在按下 Tab 后才出现补全候选，且所有候选都直接展开长描述，既不实时也没有重点。用户希望仿照 Claude 把输入 `/` 后的交互升级为动态命令面板。

## 目标

- G1：输入以 `/` 开头时自动渲染命令面板，候选随输入实时变化。
- G2：面板默认显示命令/Skill 的中文短描述；方向键聚焦到某项时才展示完整描述。
- G3：Tab 补全、Enter 执行、Esc 关闭的交互保持顺畅，不打断普通输入。
- G4：面板视觉与普通对话文本明确区分，但保持 ASCII、无颜色和窄屏可用。
- G5：仓库内命令与 Skill 的描述统一为中文且简短。

## 功能需求

### F1：输入触发与实时过滤

输入框内容以 `/` 开头时立即渲染候选；继续输入时按命令名和别名前缀实时过滤；输入不以 `/` 开头或已包含空格（命令已完整）时收起面板。

### F2：候选来源

候选来自命令注册表（内置命令 + 动态注册的 Skill 命令），隐藏命令不参与；候选顺序保持注册顺序。

### F3：短描述与完整描述

- 未聚焦行只显示短描述，超宽时截断加省略号。
- 聚焦行在其下方展示完整描述，超出终端宽度时自动换行，不横向溢出。
- 描述来自命令定义的 description；仓库内置命令与 Skill 的 description 为中文短句。

### F4：键盘交互

- Tab：单候选直接补全并追加空格；多候选保持面板并选中首个（既有行为）。
- 方向键：面板打开时循环移动焦点；面板关闭时沿用历史输入导航。
- Enter：输入与聚焦候选的命令名/别名完全一致时直接执行；否则把候选值写入输入框并收起面板，用户继续输入参数。
- Esc：收起面板，保留当前输入。

### F5：渲染与降级

- 面板行使用高亮、缩进和完整描述换行，与普通文本区分。
- ASCII 模式不输出 `❯` 等 Unicode 装饰；无颜色模式靠加粗/明暗表达聚焦。
- 窄屏只显示前 4 个候选，完整/紧凑显示前 8 个，超出时显示“还有 N 个候选”。

## 非功能需求

- N1：每次按键只做一次候选计算，不依赖网络或外部进程。
- N2：面板行和描述不超出终端宽度，不遮挡状态栏。
- N3：不改变命令注册、分发、Skill 执行和权限流程。
- N4：新增注释与 Git 提交信息使用中文。

## 不做的事

- 不把普通工具加入命令面板（工具不是斜杠命令）。
- 不做面板持久化、历史搜索或插件市场。
- 不改变命令注册中心的补全语义。

## 验收标准

- AC1：输入 `/` 即出现面板，输入 `/pe` 只剩 `/permission` 等匹配项。
- AC2：未聚焦行显示短描述，聚焦行显示完整描述且不越界。
- AC3：Tab 单候选补全、多候选进入面板；Enter 对完整命令直接执行、对部分输入选中候选。
- AC4：ASCII、无颜色、55/80/120 列下均可正常使用且无 Unicode 装饰泄漏。
- AC5：`pnpm check` 全量通过。

## 增量：面板下沉与整行高亮

### F6：面板位置

- 输入框用上下两条边框闭合；候选面板渲染在输入框下方，不进入输入框内部。
- 边框与面板按应用层实际内容宽度排版（终端列数减去左右各 1 列内边距），避免长边框在终端里折行。

### F7：左命令右描述

- 每个候选行固定左列命令名、右列短描述，右列按剩余宽度截断并保持对齐。

### F8：聚焦整行高亮

- 聚焦行把命令名与同行描述作为一个整体反色高亮，不再只高亮命令名。
- 聚焦行下方仍展示完整描述，作为补充说明，不与普通文本混排。

### 验收补充

- AC6：候选行同时包含命令名与描述，聚焦时命令和描述一起高亮。
- AC7：输入框上下边框完整，候选出现在第二条边框之后。
