# BetterCode 终端视觉与交互系统 Spec

## 背景

BetterCode 已具备对话、Agent Loop、工具调用、权限确认、斜杠命令、Skill、子 Agent 和团队协作能力，但当前终端界面仍以普通文本、简单横线和单一消息样式为主。启动时缺少可记忆的品牌形象，模型、模式、权限和 Token 信息没有稳定的视觉层级；`/help`、`/status` 等本地命令被渲染为普通助手消息；思考、工具执行、权限等待等状态主要依赖静态文字表达。

本章把 BetterCode 的交互界面升级为组件化 TUI 工作台。设计原则参考成熟终端 Agent 的对话优先、键盘优先、稳定状态区、渐进披露和低干扰反馈，但不复制其他产品的品牌素材、角色或具体视觉资产。

## 目标

- G1：建立 BetterCode 独立、统一且可长期使用的终端视觉语言。
- G2：通过原创虚拟形象、启动品牌区和运行时标记形成稳定品牌识别。
- G3：让模型、Agent 模式和权限模式始终在底部状态区可见。
- G4：精致呈现 Token、缓存、上下文、会话和团队等运行信息，并按终端宽度自动降级。
- G5：让对话、命令结果、系统通知、警告、错误和交互请求拥有清晰不同的展示层级。
- G6：通过细腻动态反馈表达思考、执行、等待选择和完成状态，不干扰持续编码。
- G7：保持现有业务能力、快捷键和 Agent 行为不变，只升级呈现与交互入口。

## 功能需求

### F1：启动品牌区与原创虚拟形象

BetterCode 每次启动交互界面时展示一次品牌区，包含 BetterCode 名称、原创蜡笔风少年虚拟形象“小码”、当前版本和简短欢迎信息。完整形象控制在 6 至 8 行终端高度，不直接复刻蜡笔小新或其他受版权保护角色的外貌、服装、台词和标志性动作。

启动区只在进程启动时完整展示；清空对话、恢复会话和切换模式不得重复刷出完整形象。进入工作状态后，思考、权限请求和重要通知使用简化品牌标记延续形象识别。

### F2：常驻自适应双层状态栏

界面底部提供常驻状态栏。第一层始终显示当前模型、Agent 模式和权限模式；团队模式激活时显示团队或协调者标记。无论是否正在流式输出、等待权限、显示补全菜单或执行本地命令，这三个核心状态都不得消失。

第二层按可用宽度显示 Token 输入、输出与总量、缓存命中、上下文占用、会话短标识、活动 Skill、后台任务或团队提醒。信息按优先级逐项收缩或隐藏，不允许无控制换行破坏输入区。

### F3：终端能力与宽度降级

完整模式使用 Unicode 线框、256 色和双层状态；紧凑模式缩短标签、隐藏低优先级指标；窄屏模式保留模型、模式、权限和最小输入区，其他状态通过 `/status` 查询。

无颜色环境、`NO_COLOR`、`TERM=dumb` 或不支持 Unicode 的环境使用 ASCII 边界和无颜色语义标记。降级只能减少装饰，不得丢失权限风险、错误、当前模式等必要信息。

### F4：结构化展示模型

界面展示内容不再只有“用户/助手加字符串”一种形态。至少区分以下内容：

- 用户任务与普通助手回复。
- 模型思考和当前流式回复。
- 本地命令结果面板。
- 成功、提示、警告和错误通知。
- 工具调用与工具结果摘要。
- 权限请求和其他需要用户选择的交互面板。
- 团队、子 Agent、上下文压缩和记忆保存事件。

不同类型使用一致的标题、前缀、缩进、边界和语义色，不依赖解析任意文本来猜测类型。

### F5：结构化本地命令面板

`/help` 使用命令目录面板展示命令名、参数提示、说明和必要别名，并按功能分组；`/status` 使用分组状态面板展示模型、会话、权限、Token、记忆、Skill、子 Agent 和团队信息；`/memory`、`/permission`、`/session`、`/tasks` 和 `/team` 使用适合各自数据的结构化布局。

未知命令、用法错误和命令异常使用命令错误通知，不伪装成模型回复。命令面板保留在对话历史中，但视觉上可明确识别为本地确定性结果。

### F6：对话与信息层级

用户输入使用稳定提示符和强调色；助手回复保持正文优先，不包进厚重卡片。思考内容使用弱化样式并与最终回复分隔。系统通知采用短标题和有限正文，避免所有事件都追加为长篇助手消息。

工具调用默认展示工具名和阶段，完成后收敛为单行摘要；错误或需要用户行动时展开原因。超长内容继续由现有上下文与工具结果机制限制，不因视觉改造无界进入界面。

### F7：细腻动态活动反馈

模型请求、思考、权限检查、工具执行、上下文压缩和后台任务切换时显示轻量活动指示。活动区包含简化虚拟形象标记、单个动画指示符、当前阶段和必要的轮次或工具名。

动画只作用于当前活动区域，不重复重绘已经完成的历史。阶段完成后活动区收敛为最终内容，不留下持续闪烁元素。用户取消、流错误或权限拒绝时立即停止动画并展示对应终态。

### F8：统一交互请求面板

权限请求使用带风险等级、工具、目标、规则和可选动作的焦点面板。当前选项有明确高亮，支持现有单键快捷选择，并补充方向键与 Enter 选择；执行命令的高风险说明保持可见。

回滚、命令补全以及后续需要用户选择的交互复用统一焦点、选中项、帮助行和取消语义。任一时刻只允许一个交互面板获得键盘焦点，避免输入框同时消费按键。

### F9：精致输入区与补全菜单

输入区与底部状态栏形成统一工作区，使用稳定边界和提示符区分可输入、禁用和等待状态。补全菜单显示在输入区上方或内部固定区域，候选切换不得推动状态栏跳动。

输入历史、Tab 补全、上下选择、Enter 提交、Esc 关闭、Ctrl+C 取消和 Ctrl+B 转后台等现有能力继续可用，并在相关状态出现时显示简短键盘提示。

### F10：状态同步与刷新

模型名称、模式、权限、Token、缓存、会话、Skill、子 Agent 和团队状态变化后，底栏在同一轮界面更新中反映新值。状态栏不依赖执行 `/status` 后才刷新，也不得显示已经失效的权限或模式。

Token 用量没有数据时显示有意设计的空状态，不显示一串零值；上下文容量可用时展示占用比例或紧凑数值，不可用时安全省略。

### F11：官方主题与语义色

本章提供一套 BetterCode 官方主题，配色克制、专业，并通过少量明亮色体现品牌个性。主题定义统一管理品牌色、正文、弱化文字、成功、提示、警告、危险、边界、选中和活动状态。

颜色只用于增强语义，任何关键信息都必须同时由文字、符号或位置表达。普通回复正文不大面积着色，避免长时间使用产生视觉疲劳。

### F12：启动诊断与异常呈现

Provider、权限、MCP、Skill 和子 Agent 启动诊断在品牌区之后以紧凑通知展示。无诊断时不产生空面板；多条诊断按来源分组并保持秘密脱敏。

终端宽度变化、动画计时器异常或单个展示组件无法格式化内容时，不得使 Agent、权限决策或退出流程崩溃；界面应退回可读纯文本。

## 非功能需求

- N1：完整布局面向现代 UTF-8、256 色终端；所有必要能力必须在 ASCII 无颜色模式下可用。
- N2：宽度变化后布局保持确定性，不出现文本覆盖、无限换行或状态栏消失。
- N3：动画刷新频率保持克制，空闲时不运行计时器；退出、完成和取消后必须释放计时器。
- N4：已完成历史使用稳定渲染路径，活动动画不得导致全部历史持续重绘或终端滚动抖动。
- N5：本地命令的结构化结果来自明确数据结构，不通过正则解析已格式化字符串恢复语义。
- N6：命令域和业务域不依赖 Ink 组件；结构化展示契约保持渲染框架中立。
- N7：关键组件支持纯函数或受控终端渲染测试，覆盖完整、紧凑、窄屏和无颜色模式。
- N8：现有 411 项测试、命令行为、权限语义、Agent Loop、会话恢复和快捷键不得回归。
- N9：新增源码注释和 Git 提交信息使用中文，产品名称统一为 BetterCode。
- N10：虚拟形象为 BetterCode 原创资产，不使用第三方角色名称、肖像、台词或可识别复制品。

## 不做的事

- 不实现用户自定义主题、主题市场或浅色/深色主题切换。
- 不把终端界面改造成固定侧栏的全屏 IDE Dashboard。
- 不加入图片协议、Sixel、Kitty Graphics 或浏览器图片渲染。
- 不加入声音、系统通知或桌面动画。
- 不改变 Agent Loop、权限规则、工具执行、命令语义和 Provider 协议。
- 不重写 Markdown 解析器；本章只处理 BetterCode 自有结构化内容和现有纯文本回复。
- 不复制 Claude、Codex、蜡笔小新或其他产品与角色的专有视觉资产。

## 验收标准

- AC1：启动 BetterCode 时只出现一次完整“小码”形象和品牌信息，清屏、恢复会话与模式切换不重复展示。
- AC2：空闲、流式输出、工具执行、权限等待、补全菜单和回滚面板状态下，底部始终能看到模型、模式和权限。
- AC3：宽终端展示双层完整状态；中等宽度自动缩短；窄终端保留模型、模式和权限且没有重叠或失控换行。
- AC4：`NO_COLOR`、`TERM=dumb` 和 ASCII 降级模式下，所有关键状态、风险和选中项仍可辨认。
- AC5：`/help` 显示分组命令目录，`/status` 显示分组运行状态，两者均可与普通助手回复视觉区分。
- AC6：`/memory`、`/permission`、`/session`、`/tasks` 和 `/team` 返回结构化本地面板，未知命令返回命令错误通知。
- AC7：模型请求、工具执行和上下文压缩期间活动指示会变化；完成、取消和失败后动画立即停止并留下稳定终态。
- AC8：权限面板同时支持单键快捷键与方向键加 Enter，选项焦点明确，拒绝或允许只提交一次决定。
- AC9：输入历史、命令补全、Ctrl+C、Ctrl+B、回滚和会话恢复行为保持可用，交互面板出现时输入框不抢按键。
- AC10：Token 与缓存状态采用统一紧凑格式；没有 usage 时显示简洁空状态，状态变化后无需 `/status` 即刷新。
- AC11：启动诊断按来源分组、无诊断无噪声，认证信息和秘密不进入品牌区、通知或快照。
- AC12：终端渲染测试覆盖至少 120、80、55 列和无颜色模式，输出无重叠、截断越界或缺失核心状态。
- AC13：类型检查、UI 聚焦测试、全量自动化测试、静态扫描和差异检查全部通过。
- AC14：实际运行一次启动、帮助、普通对话、工具调用、权限确认和退出流程，观察到统一视觉语言且终端正常恢复。

## 增量：移除底部状态栏与统一文字色

### 变更背景

界面底部的常驻状态栏（模型、模式、权限、Token、会话等状态文本及其上部分割线）不再保留。运行状态信息继续由 `/status` 结构化面板按需查询，避免底部常驻信息在终端里造成视觉噪音。

### 变更内容

- 删除 `src/ui/status-bar.tsx` 与 `src/ui/status-bar.test.ts`；`App` 不再收集和渲染 `StatusBarState`。
- 全局文字色统一为黑底下的白/灰白：正文使用白色；弱化文字通过白色加 `dimColor` 呈现灰白。
- 品牌色、提示符、语义通知（成功/警告/危险）和选中高亮保留少量明亮色，只用于特殊信息，不用于普通正文。
- 原有 `/status`、`/help`、`/memory` 等本地命令行为不变。

### 验收补充

- AC15：启动帧不再出现底栏状态文本（模型/模式/权限/会话）与底栏分割线。
- AC16：彩色终端下普通文字为白色或灰白，特殊信息才使用品牌色、提示色或语义色。

## 增量：输入光标

输入框聚焦且可用时，在输入文本末尾显示可见光标（Unicode 模式 `█`，ASCII 模式 `_`）；禁用或失焦时不显示，避免与权限面板等交互状态混淆。

## 增量：命令面板聚焦展开与更白文字

- 聚焦命令后，完整描述在右侧描述列原地展开并保持右对齐，不再另起补充行；超长时从左侧截断保留右缘，避免挤掉命令名或越界。
- 命令面板未聚焦候选行使用纯白文字（`BETTERCODE_THEME.text`），去掉 `dimColor` 弱化，黑底终端下更清晰；聚焦行保留整行反色高亮。
- 新增 `truncateStart` 显示宽度工具，与既有 `truncateDisplay` 共用 `Intl.Segmenter` 粒度，保证中英文与组合字符宽度正确。

## 增量：像素文字启动横幅

- 移除启动界面的 ASCII/Unicode 虚拟形象，改为像素文字横幅「BETTERCODE」：全大写、独立占块、7 行高；窄屏自动降级为 5 行高 3 列宽的紧凑像素字。
- 横幅使用品牌色渲染，品牌色由 magenta 调整为橘黄（`#FFA500`）。
- ASCII/窄屏模式下使用 `#` 块代替 `█`，不输出 Unicode 装饰，也不越界。

### 验收补充

- AC17：启动帧展示像素文字「BETTERCODE」横幅，不再出现虚拟形象。
- AC18：55 列 ASCII 环境下横幅宽度不越界且不输出 `█` 等 Unicode 装饰。

## 增量：立体横幅

- 完整宽度下将平面像素字升级为带棱角的立体横幅：采用 ANSI Shadow 风格字表完整渲染「BETTERCODE」，固定 6 行、约 83 列，字符由 `█`、`╗`、`╔`、`╚`、`╝`、`═`、`║` 组成，呈现立体浮雕效果。
- 立体横幅仅用于 Unicode 且终端宽度不小于 84 列；80 列及以下紧凑终端、ASCII 与 55 列窄屏继续使用平面像素字降级，保证不越界、不输出 Unicode 装饰。
- 品牌色保持橘黄（`#FFA500`）。

### 验收补充

- AC19：完整宽度启动帧展示立体浮雕风格「BETTERCODE」横幅，内容确为 BETTERCODE，不再使用平面方块字或示例原文。

## 增量：FIGfont 连贯字标组件

- 废弃手工拼接、删间距或添加贯穿横线的一体化方案；宽屏启动横幅改由独立 `Wordmark` 组件通过 FIGfont 的 controlled smushing 排版生成。
- 采用 Slant 字体，以 `/`、`\\`、`_` 和括号形成圆滑斜面；字体引擎负责字距拟合和边缘合并，输出固定为 5 行、最大 64 列。
- 字标为纯 ASCII，在支持或不支持 Unicode 的宽屏终端均可稳定显示；窄屏继续使用原有 5 行紧凑像素字。
- FIGfont 加载失败时回退到预生成的同款 Slant ASCII 快照，不能改变视觉或影响 BetterCode 启动。

### 验收补充

- AC20：64 列以上非窄屏终端展示完整、可读、无贯穿式辅助横线的 Slant「BETTERCODE」字标。
- AC21：55 列、Unicode 关闭及 FIGfont 异常场景均有确定降级，不发生换行、乱码或启动失败。

## 增量：整体连通的立体字标

- Slant 斜体字标不再作为宽屏启动横幅。宽屏恢复 ANSI Shadow 的正面块与箱线阴影，并由逐字形组合器负责拼装，不能再依赖通用 smushing 的视觉近似。
- `BETTERCODE` 的九个字间边界必须各有一处局部亮面连接，连接高度错开；所有非空单元最终组成一个四向连通图，不允许用顶部横梁、底部基线或硬删空格伪造整体性。
- 正面和连接使用亮橘黄 `#FFA500`，斜面与阴影使用深橘 `#B45309`，无颜色终端仍通过 `█` 与箱线字符保留立体层次。
- 完整字标固定 6 行、最大 83 列，仅在支持 Unicode 且宽度足够时显示；80 列、ASCII 与窄屏继续使用已有平面像素字。
- FIGfont 加载或字形边界校验失败时，回退到与正常组合结果完全一致的静态快照。

### 验收补充

- AC22：宽屏横幅的九个相邻字母边界全部存在真实接触点，整个非空图形只有一个连通分量。
- AC23：横幅包含可辨认的正面与箱线阴影，彩色终端使用亮橘正面和深橘阴影，且没有新增贯穿整词的顶部或底部辅助线。
- AC24：83 列宽度边界、ASCII/80 列/55 列降级和 FIGfont 异常回退均稳定，不换行、不乱码。

## 增量：原创单体像素 Logo 与启动动画

### 变更背景

FIGfont 与 ANSI Shadow 都以独立字母排版为前提，即使通过删字距或补连接线处理，视觉上仍会出现十个字符并排、顶部横梁贯穿或连接点生硬的问题。本增量废弃通用字体引擎，改用 BetterCode 原生字模和共享像素拓扑。

### 变更内容

- 新增 `LogoRenderer`，使用 5×7 原创字模生成 `BETTERCODE`；相邻字形按 4 列步长重叠一列，九个边界在不同高度共享像素，完整图形必须是单一四向连通分量。

## 增量：启动 Logo 可读性修正

### 变更背景

原单体方案通过重叠字形建立连接，连接像素会进入字母主体，导致 `T`、`E`、`R`、`C` 和 `O` 的负空间被破坏。动画虽能正常播放，但最终画面无法快速辨认出 `BETTERCODE`。

### 变更内容

- 字模改为 4×7、字形起点按 5 个逻辑列递进；宽屏横向双倍渲染后固定为 98 列，字母主体之间保留两个终端列的负空间。
- 九处连接只允许写入各自字间负空间，使用最低亮度 `░`，不得覆盖橙色主笔画；同一边界的其余六行必须保持空白。
- 圆角字形相邻行发生一格错位时，使用低亮度 `▒` 补一个倒角像素，使圆润轮廓从对角接触升级为真实四向连通。
- 主笔画继续使用 `█▓▒` 的明暗层次，字形辨识优先于连接装饰；禁止通过字形重叠、贯穿横梁或侵入字腔来制造整体感。

### 验收补充

- AC29：最终帧可直接辨认为 `BETTERCODE`，十个字形的主要笔画和负空间不被连接层覆盖。
- AC30：九个字间空隙各仅有一行暗色连接，完整 Logo 与每个圆角字形均属于同一个四向连通分量。
- AC31：120 列真彩终端下 Logo 居中、不换行，逐行动画、状态延迟展示及 Ctrl+C 光标恢复保持正常。

## 增量：终端崩溃加固与 Apple Terminal 安全渲染

### 变更背景

macOS 自带 Terminal 的文本视图在流式重绘含 U+2014 破折号的 UTF-8 内容时，其内置分词器（CoreNLP/MeCab）可能出现递归后 SIGBUS，导致整个终端进程崩溃。BetterCode 侧需要降低重绘频率，并在该终端上把高风险字符转换为 ASCII 后再送显示层，同时保留会话与文档的原始内容。

### 变更内容

- 流式输出改为固定 60ms 合帧刷新，`text_delta` 与 `thinking_delta` 不再逐 token 触发整屏重绘；活动指示器动画频率从 100ms 降为 250ms，降低长回复与等待期间的终端重绘压力。
- `TerminalCapabilities` 新增可选 `appleTerminal`，从 `TERM_PROGRAM=Apple_Terminal` 检测；`TerminalEnvironment` 新增 `termProgram` 可注入字段。
- 新增 `terminalSafeText`：仅在 `appleTerminal` 为真时，把显示层文本中的 U+2014 替换为 `--`、U+2013 替换为 `-`；普通终端原样返回。会话存档、Markdown AST 与工具结果数据不做修改。
- 安全替换覆盖 Markdown 正文与思考、纯文本对话、通知标题、输入框显示文本、命令候选标签与描述、交互面板（权限确认、回滚检查点）的详情与选项。
- 未处理的 Promise 拒绝记录到 `.bettercode/logs/runtime-errors.log` 后继续运行；未捕获异常记录后退出，避免后台异步错误直接把 Agent 会话关掉。

### 验收补充

- AC35：流式回复按合帧刷新，长文本不逐 token 整屏重绘；动画在低动态与 CI 环境继续降级。
- AC36：`TERM_PROGRAM=Apple_Terminal` 时所有显示出口的 U+2014/U+2013 均以 ASCII 展示，非 Apple 终端保持原文。
- AC37：安全替换只影响显示层，会话文件与 Markdown 解析结果保持原始破折号。
- AC38：后台异步错误只记录日志不退出进程；未捕获异常按固定格式记录后退出，不产生不可诊断的静默消失。

## 增量：Apple Terminal 再次加固

### 变更背景

上一轮破折号替换后，macOS 自带 Terminal 仍在流式长回复与 `/session` 交互期间出现多次进程级崩溃。崩溃报告显示均为 Terminal 自身在 attributed string 绘制/中文输入法事件里的堆内存损坏（`BUG IN CLIENT OF LIBMALLOC: memory corruption of free block`），其中一次系统文本分析器（CoreNLP/MeCab）直接读取了含 U+2014/U+2015 的 UTF-8 字节。BetterCode 侧继续做三层降低触发概率的加固。

### 变更内容

- 新增 `wrapDisplay`：按显示宽度硬换行，流式文本、纯文本对话、thinking 与用户消息不再以超长单行写进终端，避免 Terminal 文本视图对大范围 attributed string 做高频替换。
- `terminalSafeText` 的替换范围扩展为破折号族：U+2014/U+2015/U+2E3A/U+2E3B 替换为 `--`，U+2012/U+2013/U+2212/U+FE58/U+FE63 替换为 `-`，覆盖 macOS 文本分析器崩溃涉及的字符。
- Apple Terminal 下流式合帧间隔由 60ms 放慢到 120ms，活动指示器动画由 250ms 放慢到 500ms；其他终端维持原频率。

### 验收补充

- AC39：任意长度的流式文本与 thinking 在显示层都被硬换行，单行显示宽度不超过终端列宽。
- AC40：Apple Terminal 下所有破折号族字符均以 ASCII 展示，普通终端保持原文。
- AC41：非 Apple 终端渲染频率与动画频率保持不变。
