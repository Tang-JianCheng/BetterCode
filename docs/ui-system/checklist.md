## 品牌与启动

- [x] **C1：启动品牌区只出现一次**
  启动时显示 BetterCode 名称、版本、欢迎语和完整“小码”形象；清屏、恢复会话、切换模式后不重复。（验证：组件生命周期测试加真实 TUI 操作；覆盖 AC1）

- [x] **C2：虚拟形象保持原创**
  Unicode 与 ASCII 形象均不包含第三方角色名称、台词、服装标志或可识别复制轮廓。（验证：资产审阅和静态扫描；覆盖 N10）

- [x] **C3：完整与降级形象均可读**
  120/80 列使用完整形象，55 列或 ASCII 模式使用紧凑形象，每行均不超过可用宽度。（验证：品牌区渲染矩阵；覆盖 AC1、AC3、AC4）

- [ ] **C4：启动诊断无噪声且分组**
  无诊断时品牌区后直接进入输入；有 Provider、权限、MCP、Skill 或 Agent 诊断时按来源展示紧凑通知。（验证：启动状态矩阵；覆盖 AC11）

- [ ] **C5：启动信息保持脱敏**
  API Key、MCP header、环境变量值和用户目录秘密不进入品牌区、诊断面板或捕获帧。（验证：注入测试秘密并精确扫描；覆盖 AC11）

## 状态栏

- [ ] **C6：核心状态始终可见**
  空闲、流式、工具执行、权限等待、补全和回滚状态下，底栏均包含模型、Agent 模式和权限模式。（验证：App 状态矩阵；覆盖 AC2）

- [x] **C7：完整双层状态信息正确**
  120 列终端展示模型、模式、权限、Token、缓存、上下文、会话及存在的团队或任务提醒。（验证：full 状态栏帧；覆盖 AC3、AC10）

- [x] **C8：紧凑状态栏按优先级收缩**
  80 列终端先缩短标签和低优先级值，不删除模型、模式和权限，也不发生无控制换行。（验证：compact 帧与段优先级单测；覆盖 AC3）

- [x] **C9：窄屏状态栏不重叠**
  55 列终端保留三个核心状态，长模型名安全截断，所有行显示宽度不超过 55。（验证：narrow 帧宽度扫描；覆盖 AC3）

- [ ] **C10：状态变化即时刷新**
  `/plan`、`/do`、权限切换、usage 更新、Skill 激活和团队提醒发生后，下一稳定帧立即显示新状态，无需执行 `/status`。（验证：状态更新交互测试；覆盖 AC10）

- [x] **C11：usage 空状态简洁**
  尚无 Token 数据时不显示五个零值；得到 usage 后显示输入、输出、缓存和总量的统一紧凑格式。（验证：空/有 usage 对比帧；覆盖 AC10）

- [x] **C12：状态栏没有旧横线实现**
  根界面不再使用 `'-'.repeat(columns)` 或独立 Token 裸文本行。（验证：静态扫描和实际帧；覆盖 G4）

## 结构化内容

- [x] **C19：展示契约与 Ink 解耦**
  presentation 与 command presenter 不导入 React、Ink、ANSI 或 stdout。（验证：依赖静态扫描；覆盖 N5、N6）

- [x] **C20：非法展示文档失败关闭**
  空标题、错列表格和超限详情被构造器拒绝，不产生半有效面板。（验证：builders 错误矩阵；覆盖 N5）

- [x] **C21：普通对话保持正文优先**
  用户任务有稳定提示符，助手回复无厚重卡片，thinking 使用弱化分区且不覆盖最终正文。（验证：conversation 渲染帧；覆盖 F6）

- [x] **C22：通知语义明确**
  success/info/warning/danger 在有色和无色模式下均可区分，详情只在存在时渲染。（验证：notice 矩阵；覆盖 F4、F11）

- [ ] **C23：长内容保持有界**
  超长标题、键值、表格和列表在各宽度下安全换行或截断，不产生横向越界。（验证：极端内容帧扫描；覆盖 N2）

- [x] **C24：模型文本不被误判为命令面板**
  助手正文即使包含 `/help`、边框字符或伪标签，也按普通 conversation 渲染。（验证：伪造内容测试；覆盖 F4）
