# BetterCode Worktree 隔离系统 Spec

## 背景

BetterCode 已支持定义式和 Fork 式子 Agent。每个子 Agent 拥有独立的消息、权限、Token、上下文和工具读取状态，但文件操作仍指向主 Agent 的项目目录。多个 Agent 并发修改同一仓库时，可能互相覆盖文件、读取到对方的中间状态，甚至在清理过程中破坏尚未完成的工作。

本章为 BetterCode 增加基于 Git Worktree 的文件系统隔离。只有角色声明需要 Worktree 的定义式子 Agent 进入隔离目录；Fork 子 Agent 继续共享主工作区。隔离子 Agent 从主工作区当前已提交版本建立专属分支和工作目录，在不复制完整仓库的前提下并行工作。

## 术语

- **主工作区**：启动 BetterCode 时所在 Git 仓库的原始工作目录。
- **隔离工作区**：BetterCode 为单个定义式子 Agent 创建的 Git Worktree。
- **安全名称**：经过严格校验、可映射为隔离目录相对路径和专属分支后缀的名称。
- **创建基点**：创建隔离工作区时主工作区当前 `HEAD` 指向的提交。
- **快速恢复**：目标目录已经存在时，仅根据文件系统和 BetterCode 元数据恢复运行时引用，不执行 Git 命令的创建路径。
- **租约**：调用方进入隔离工作区后持有的活动引用；租约未全部释放时，工作区仍被视为使用中。
- **未推送提交**：相对创建基点新增、但尚未被对应远程上游包含的提交。专属分支没有上游且存在新增提交时，也视为未推送。

## 目标

- 为需要隔离的定义式子 Agent 创建仓库内、Git 不追踪的独立工作目录。
- 保证每个隔离子 Agent 在专属分支中读写文件，不干扰主工作区或其他子 Agent。
- 通过显式绝对工作目录驱动工具和运行时，不修改进程级当前目录。
- 支持创建、快速恢复、进入、退出、安全删除和过期清理的完整生命周期。
- 初始化隔离工作区所需的本地配置、Git hooks、依赖软链和被忽略运行文件。
- 对名称、路径、符号链接、元数据归属和删除条件实施严格校验。
- 在存在未提交修改、未推送提交或有效租约时保护工作区，避免自动丢失成果。
- 共享 Provider、Hook 定义等基础设施，同时让路径相关状态按绝对工作目录隔离。

## 功能需求

### F1：角色隔离声明

定义式子 Agent 的角色 frontmatter 必须新增可选的 `isolation` 字段。字段只允许表示“不隔离”或“使用 Worktree”两种状态，缺省时保持现有共享主工作区的行为。声明使用 Worktree 的角色在开始执行前必须先获得隔离工作区，准备失败时不得退回主工作区继续执行。

Fork 子 Agent 不读取角色定义，也不创建 Worktree，继续共享主 Agent 的当前工作目录。角色定义热更新后，新任务使用最新隔离声明；已经运行的任务不迁移工作目录。

### F2：安全名称与路径约束

隔离子 Agent 的安全名称由 BetterCode 根据角色名和任务编号生成，格式为 `<角色名>/<任务编号>`，不向模型开放任意目录参数。同一角色的并发任务必须得到不同名称。

Worktree 生命周期入口仍必须对所有名称执行统一校验：只允许 ASCII 小写字母、数字、点、下划线、短横线和用于分段的正斜杠；总长度和单段长度必须有明确上限；不允许空段、绝对路径、反斜杠、控制字符、`.`、`..`、连续点号、首尾点号或其他不合法 Git 引用形式。校验失败必须在接触文件系统或执行 Git 前返回结构化错误。

所有路径判断必须先得到规范化绝对路径并解析已经存在的符号链接，再验证目标位于当前主仓库的 Worktree 根目录内。字符串前缀相似但不处于该目录树中的路径不得通过校验。

### F3：目录、分支与创建基点

隔离目录固定放在主仓库的 `.bettercode/worktrees/<安全名称>` 下，对应本地分支固定为 `bettercode/worktree/<安全名称>`。Worktree 根目录必须被 Git 忽略，运行数据不得进入项目提交。

新分支统一从主工作区创建时的当前 `HEAD` 建立。主工作区未提交或未暂存的修改不得复制进隔离工作区。每个隔离工作区独占一个专属分支，创建时必须拒绝复用被其他 Worktree 占用的分支。

### F4：创建与快速恢复

首次创建必须按顺序完成名称校验、仓库确认、目录冲突检查、专属分支与 Worktree 建立、元数据登记和环境初始化。必需步骤失败时必须尽力回滚本次已经创建的目录、分支和元数据，不得删除创建前已经存在的内容。

BetterCode 必须在 `.bettercode` 运行数据中记录每个隔离工作区的仓库身份、规范化主工作区路径、规范化 Worktree 路径、安全名称、分支、创建基点、创建时间、最后使用时间和生命周期状态。

目标目录已存在时进入快速恢复：只读取目标目录和 BetterCode 元数据，不调用 Git。只有目录和元数据在仓库身份、路径、名称及分支登记上完全一致时才能恢复；元数据缺失、不一致或指向仓库外部时必须拒绝接管，不得覆盖、删除或自动修复未知目录。

### F5：进入、退出与租约

进入隔离工作区必须返回包含规范化绝对工作目录的租约。调用方将该目录作为显式工作上下文传给工具和运行时，不得通过 `chdir` 或其他进程级目录切换实现进入。

同一隔离工作区允许多个内部组件同时持有租约。退出操作只释放对应租约，并在最后一个租约释放时更新最后使用时间；重复释放必须安全且不得影响其他租约。存在有效租约时，普通删除、强制删除和后台过期清理都必须拒绝。

### F6：环境初始化

Worktree 创建后必须执行环境初始化。BetterCode 提供内置惯例：复制主工作区中存在的常见本地环境配置，配置隔离工作区使用当前仓库的 Git hooks，并在主工作区存在大型依赖目录时为隔离工作区建立软链。当前项目的默认大型依赖目录至少包含 `node_modules`。

项目配置必须能够追加复制文件、复制被 Git 忽略但运行必需的文件，以及建立依赖软链的规则。规则必须区分必需和可选：Worktree、元数据等核心步骤始终必需；内置初始化规则默认可选；项目规则可显式声明为必需。必需规则失败会使创建失败并触发回滚，可选规则失败只产生有界诊断并继续。

复制和软链规则的源必须位于主工作区内，目标必须位于隔离工作区内。规则应用前必须解析已有符号链接并重新执行边界检查，不得借助绝对路径、父目录、符号链接或 glob 结果逃逸。初始化不得覆盖 Worktree 中已存在且内容来源不明的文件。

### F7：按工作目录创建运行时作用域

隔离子 Agent 必须使用与隔离工作区绑定的运行时作用域。该作用域至少包含独立的工具注册与路径守卫、权限工作目录、上下文管理、工具执行状态、系统提示环境信息、项目指令和记忆访问入口。所有文件和命令工具都必须从当前作用域取得显式绝对工作目录。

Provider 客户端、Hook 规则定义、角色定义快照和不含工作目录可变状态的基础设施可以共享。共享基础设施不得保存“当前 Worktree”这类进程级可变指针，也不得使一个子 Agent 切换另一个 Agent 的工作目录。

### F8：路径相关缓存隔离

文件内容、编辑前读取状态、系统提示环境信息、项目指令、记忆和其他路径相关缓存必须使用规范化绝对路径作为键，不得只使用相对路径或依赖全局当前目录。相同相对路径在主工作区和不同 Worktree 中必须形成不同缓存项。

创建、进入和退出 Worktree 时不要求清空全局缓存。任务结束后可以释放该运行时作用域拥有的临时状态，但不得清理其他工作目录仍在使用的缓存。

### F9：子 Agent 生命周期集成

声明 Worktree 隔离的定义式子 Agent 在进入运行状态前必须完成工作区创建或快速恢复、环境初始化和租约获取。BetterCode 必须向子 Agent 的环境指令注入当前绝对路径、专属分支、创建基点以及“所有工具必须在该目录执行”的说明。

无论子 Agent 正常完成、失败、取消、超时转后台还是应用关闭，运行路径都必须通过统一的最终清理逻辑释放租约。前台转后台不得重建 Worktree、改变任务编号或丢失现有运行时状态。

任务状态和事件中必须能够观察隔离是否启用、工作区路径、分支以及最终是已删除还是因保护原因被保留。路径信息只用于本地运行与诊断，不得写入稳定 System Prompt 缓存通道。

### F10：变更与未推送提交保护

删除前必须检查有效租约、未提交修改和未推送提交。未提交修改包括已暂存、未暂存和未追踪文件。未推送提交以创建基点、当前专属分支和远程上游共同判断；没有上游但相对创建基点存在新提交时必须判定为未推送。

默认删除在任一保护条件命中时必须拒绝，并返回具体原因、工作区路径和分支，不能只返回笼统失败。调用方明确传入强制删除意图时，可以绕过未提交和未推送保护，但不能绕过活动租约、路径边界、仓库身份、元数据归属或分支归属校验。

安全删除必须同时移除 Worktree、对应专属本地分支和元数据。删除中途失败时必须保留足够元数据以便重试和诊断，不得把仍存在的目录标记为已成功删除。

### F11：任务完成后的保留策略

隔离子 Agent 完成并释放最后一个租约后，BetterCode 必须尝试安全自动清理。工作区无未提交修改且没有未推送提交时，自动删除工作目录、专属本地分支和元数据。

存在受保护内容时必须保留工作区，并把保留原因、绝对路径、分支和后续处理提示返回任务记录与主 Agent。保留不得被当作子 Agent 执行失败；子 Agent 的任务结果与 Worktree 清理结果必须分别记录。

### F12：后台过期清理

BetterCode 启动时必须扫描一次过期隔离工作区，运行期间默认每小时继续扫描。工作区默认保留期限为七天，保留期限和扫描间隔允许通过配置覆盖。

清理候选必须依次通过三层过滤：路径层确认候选位于规范化 Worktree 根目录且名称安全；归属层确认元数据、仓库身份、路径和专属分支一致且不存在有效租约；变更层确认没有未提交修改和未推送提交。任何一层失败都必须跳过候选并记录有界诊断，绝不自动升级为强制删除。

单个候选损坏、Git 检查失败或删除失败不得中断其他候选的扫描，也不得影响主 Agent 和子 Agent 主流程。清理器不得处理没有 BetterCode 元数据的未知目录。

### F13：错误、事件与可观测性

Worktree 操作必须返回稳定的成功或错误结果，至少区分名称无效、非 Git 仓库、路径越界、目录冲突、元数据不匹配、Git 创建失败、初始化失败、活动租约、存在未提交修改、存在未推送提交和删除失败。

创建、恢复、进入、退出、保留、删除和过期清理必须产生与界面解耦的生命周期事件。事件和错误文本必须限制大小，不得包含环境变量值、Provider 密钥、本地配置文件内容或其他敏感信息。

单个 Worktree 的创建、初始化或清理失败不得使 BetterCode 进程退出，也不得影响其他 Worktree 或无隔离子 Agent 的执行。

### F14：配置与兼容性

Worktree 配置必须提供稳定默认值，并支持项目级设置环境初始化规则、默认保留期限和扫描间隔。配置错误必须在启动或首次加载对应项目时给出明确诊断；无 Worktree 配置时仍能使用内置默认行为。

未声明 `isolation: worktree` 的定义式子 Agent、全部 Fork 子 Agent、主 Agent 和现有工具调用必须保持当前工作目录及行为不变。现有角色定义缺少 `isolation` 字段时必须继续合法加载。

## 非功能需求

- **N1：安全性**  所有创建、恢复、初始化和删除操作都必须经过规范化路径、符号链接、仓库身份和元数据归属校验；强制删除不能绕过这些硬边界。
- **N2：并发一致性**  并发创建同名工作区、重复恢复、租约释放和删除必须有确定结果，不得重复建分支、误减租约或删除运行中的目录。
- **N3：隔离性**  主工作区和不同 Worktree 中的相同相对路径不得共享可变读取状态、提示缓存、项目指令缓存或记忆缓存。
- **N4：兼容性**  未启用 Worktree 时，主 Agent、子 Agent、工具、权限、Hook、Skill、记忆、上下文管理、会话和 Provider 行为保持不变。
- **N5：可恢复性**  创建和删除的部分失败必须保留可诊断状态；快速恢复不得依赖 Git 命令，也不得接管未知目录。
- **N6：可观测性**  每个隔离任务都能查询工作区路径、分支、创建基点、生命周期状态、保留原因和最近错误。
- **N7：性能**  Worktree 复用 Git 对象库，不复制完整仓库；大型依赖优先软链；过期扫描不得阻塞 Agent 主循环。
- **N8：资源边界**  清理扫描、初始化 glob、事件、错误和诊断必须有数量或大小上限，避免异常项目结构造成无限遍历或内存增长。
- **N9：命名一致性**  用户可见文档、提示、事件和错误统一使用 BetterCode 名称，不得出现旧系统名。

## 不做的事

- 不实现 Worktree 分支与主分支之间的自动合并、变基、挑选提交或冲突解决。
- 不自动把主工作区后续修改同步到已经创建的 Worktree。
- 不实现多 Agent 团队拓扑、任务编排、共享黑板或自动拆分任务。
- 不让 Fork 子 Agent 创建 Worktree，也不为未声明隔离的定义式角色自动启用 Worktree。
- 不自动提交或推送子 Agent 的修改，不创建远程分支，也不替用户配置远程上游。
- 不跨 BetterCode 进程恢复正在运行的子 Agent；只恢复磁盘上的 Worktree 生命周期信息。
- 不提供容器、虚拟机或操作系统级沙箱，Worktree 只隔离同一 Git 仓库中的工作目录和分支。
- 不复制主工作区未提交修改到隔离工作区。
- 不删除缺少有效 BetterCode 元数据的未知目录或其他工具创建的 Worktree。

## 验收标准

- **AC1：角色声明**  旧角色定义无需修改即可继续加载；声明 `isolation: worktree` 的定义式任务在隔离目录运行；其他定义式任务和 Fork 任务继续使用原工作区。准备隔离失败时任务不会退回主目录执行。（覆盖 F1、F14）
- **AC2：名称与路径安全**  合法嵌套名称可映射为预期目录和分支；绝对路径、空段、`.`、`..`、连续点号、控制字符、超长名称、非法 Git 引用和符号链接逃逸在执行 Git 前被拒绝。（覆盖 F2）
- **AC3：创建基点与布局**  新工作区位于 `.bettercode/worktrees/<角色>/<任务编号>`，分支使用 `bettercode/worktree/` 前缀并从创建时主工作区 `HEAD` 建立；主工作区未提交修改不会出现在新 Worktree 中，运行目录不会被 Git 跟踪。（覆盖 F3）
- **AC4：创建回滚与快速恢复**  首次创建会写入完整元数据并执行初始化；必需步骤失败时只回滚本次资源。目录和元数据一致时可在不执行 Git 命令的情况下恢复；元数据缺失或不匹配时拒绝接管且不改动目录。（覆盖 F4）
- **AC5：租约生命周期**  多个组件可同时进入同一工作区并得到相同规范化 `cwd`；释放一个租约不影响其他租约；重复释放无副作用；存在任一活动租约时所有删除路径均拒绝。（覆盖 F5）
- **AC6：环境初始化**  存在的常见本地配置被复制，Git hooks 在隔离工作区可用，主工作区已有 `node_modules` 时隔离目录得到安全软链；项目追加的复制、忽略文件和软链规则生效。可选失败只记录诊断，必需失败触发安全回滚。（覆盖 F6）
- **AC7：显式工作目录**  并发运行两个隔离子 Agent 时，每次文件和命令工具调用都携带各自绝对 `cwd`，进程工作目录始终不变；一个 Agent 的目录切换不会改变主 Agent或另一个 Agent 的执行位置。（覆盖 F7）
- **AC8：缓存隔离**  主工作区和两个 Worktree 中同名文件拥有独立读取与编辑状态，系统提示环境、项目指令和记忆按各自绝对路径加载；进入或退出无需清空其他目录的缓存。（覆盖 F8）
- **AC9：子 Agent 集成**  隔离任务启动前完成创建或恢复并获得租约，环境指令包含正确路径与分支；正常完成、失败、取消、超时转后台和应用关闭都会释放租约，前后台切换不会重建目录或丢失状态。（覆盖 F9）
- **AC10：删除保护**  已暂存、未暂存、未追踪修改和未推送提交分别能阻止默认删除并返回明确原因；无上游且存在新提交时判为未推送。显式强制可绕过变更保护，但不能绕过租约、路径和归属校验。（覆盖 F10）
- **AC11：清理结果**  无未提交或未推送内容的任务完成后自动删除 Worktree、专属本地分支和元数据；有受保护内容时保留目录并返回路径、分支和原因，且不改变子 Agent 原始任务结果。（覆盖 F11）
- **AC12：过期清理**  启动扫描和每小时定时扫描只处理超过默认七天的候选；路径、归属和变更三层过滤均生效。活动、有修改、有未推送提交或无有效元数据的目录不会被清理，单个失败不影响其他候选。（覆盖 F12）
- **AC13：事件与错误**  Worktree 各生命周期阶段均可通过异步事件观察，常见失败映射为稳定错误码；日志、事件和任务结果不泄露环境变量、密钥或本地配置内容，单个失败不退出 BetterCode。（覆盖 F13）
- **AC14：兼容回归**  不启用隔离时，现有主 Agent、定义式与 Fork 子 Agent、权限、Hook、Skill、记忆、上下文、会话、工具和 Provider 测试保持通过；用户可见内容只使用 BetterCode 名称。（覆盖 F14、N4、N9）
- **AC15：范围确认**  系统不会自动合并、同步、提交或推送 Worktree 分支，不为 Fork 创建隔离目录，不复制主工作区未提交修改，也不删除未知目录。（覆盖“不做的事”）
